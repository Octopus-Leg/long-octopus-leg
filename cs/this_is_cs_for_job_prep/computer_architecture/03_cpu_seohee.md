# 2.3 CPU

## 레지스터
- CPU 안에 있는 작은 **임시 저장장치**임.
- 프로그램의 명령어와 데이터는 실행 전후로 레지스터에 저장됨. ➡️ 레지스터에 저장된 값을 보면 낮은 수준의 프로그램이 어떻게 작동하는지 파악할 수 있음.
- 디버깅 도구(`WinDbg`, `gdb` 등)를 통해 관찰할 수 있음.

### 레지스터 종류
- **프로그램 카운터(=명령어 포인터)**
  - 메모리에서 **다음으로 읽어 들일 명령어의 주소**를 가리키고 저장하는 레지스터임.
  - 일반적으로 값이 1씩 순차적으로 증가함.
  - 프로그램 흐름 중 `조건문`, `리턴문`을 만나 실행 순서가 점프할 때는 순차적 증가를 멈추고 카운터 값이 임의 변경됨.
- **명령어 레지스터**
  - 메모리에서 방금 읽어 들인 **현재 해석하고 실행할 명령어**를 저장하는 레지스터임.
  - 제어장치는 명령어 레지스터에 저장된 명령어를 읽어 기계어를 해석한 뒤, 컴퓨터 각 부품에 필요한 제어 신호를 발생시킴.
- **범용 레지스터**
  - 데이터와 명령어, 주소 등 어떠한 값도 자유롭고 일반적인 목적으로 담을 수 있는 멀티플레이어 레지스터임.
  - 현대 CPU 내부에는 여러 개의 범용 레지스터가 존재함.
- **플래그 레지스터**
  - ALU가 산술 및 논리 연산을 수행한 결과 혹은 CPU 상태에 대한 부가 정보인 **플래그**를 저장하는 레지스터임.
  - 플래그는 CPU가 명령어를 처리하는 과정에서 반드시 참조해야 할 상태 정보를 의미하는 비트임.
  - 대표적으로 연산 결과의 양수/음수를 판별하는 **부호 플래그**, 결과가 0인지 체크하는 **제로 플래그**, 자리올림 발생 여부를 뜻하는 **캐리 플래그**, 표현 범위를 초과했는지 알려주는 **오버플로우 플래그** 등이 있음.
- **스택 포인터**
  - 메모리 내 스택 영역에서 **가장 최근에 저장된 최상단 스택 데이터의 위치**를 가리키는 레지스터임.
  - 스택에 저장된 데이터의 위치를 가리키는 레지스터이자, 스택이 채워진 정도를 나타냄.

## 인터럽트
- CPU의 작업을 방해하는 신호를 말함.
- 인터럽트는 크게 동기 인터럽트와 비동기 인터럽트로 나뉨.
- **동기 인터럽트**
  - CPU에 의해 발생하는 인터럽트로 예외라고도 부름.
- **비동기 인터럽트**
  - 주로 입출력장치에 의해 발생하는 인터럽트로 책에서는 하드웨어 인터럽트라고 함.
  - ex) CPU가 프린터와 같은 입출력장치에게 입출력 작업을 부탁하고, 작업을 끝낸 입출력장치가 CPU에게 완료 알림을 보냄.

### 하드웨어 인터럽트
- 효율적으로 명령어를 처리하기 위해 하드웨어 인터럽트를 사용함.
- CPU에 비해 입출력장치는 연산 속도가 현저히 느림. 만약 하드웨어 인터럽트가 없다면 CPU는 입출력장치가 작업을 끝냈는지 주기적으로 확인해야 하는데, 이 방식을 **폴링**이라고 함.
- 반면 인터럽트 방식을 사용하면, CPU는 자기 할 일을 하다가 입출력장치가 완료 알림을 보낼 때만 대응하므로 **CPU 효율성을 극대화**할 수 있음.

- **하드웨어 인터럽트 처리 순서**
  1. **인터럽트 요청 신호**: 입출력장치가 CPU에 인터럽트 요청 신호를 보냄.
  2. **인터럽트 여부 확인**: CPU는 하나의 실행 사이클이 끝나고 다음 명령어를 인출하기 직전에 항상 인터럽트 요청이 와 있는지 확인함.
  3. **인터럽트 플래그 검사**: CPU는 플래그 레지스터 내부의 **인터럽트 플래그**를 확인하여 현재 인터럽트를 허용할 상태인지 판별함.
  4. **지금까지의 작업 백업**: 인터럽트를 받아들일 수 있다면 CPU는 지금까지의 작업을 메모리 내 **스택**에 백업함.
  5. **벡터 참조 및 루틴 실행**: CPU는 **인터럽트 벡터**를 참조하여 **인터럽트 서비스 루틴**의 시작 주소를 찾아내고 실행함.
     - 인터럽트 서비스 루틴(=인터럽트 핸들러): 인터럽트를 처리하기 위한 프로그램으로 어떤 인터럽트가 발생했을 때 해당 인터럽트를 어떻게 처리하고 작동해야 할지에 대한 정보로 이루어져 있음.
     - 입출력장치마다 각기 다른 인터럽트 서비스 루틴을 가지고 있음.
     - 인터럽트 벡터: 수많은 인터럽트 서비스 루틴들을 구분하기 위해 이용함. CPU는 하드웨어 인터럽트 요청을 보낸 대상으로부터 인터럽트 벡터를 전달받음.
  6. **복구 및 재개**: 서비스 루틴 실행이 완료되면, 스택에 백업해 두었던 작업을 복구해 실행을 재개함.
  > **막을 수 없는 인터럽트**: 인터럽트 플래그가 불가능으로 설정되어 있더라도 무시할 수 없는 최우선 인터럽트임. 정전, 하드웨어 치명적 고장 등 긴급 조치가 필요한 상황에 발생함.

### 예외
- CPU는 예외가 발생하면 하던 일을 중단하고 해당 예외를 처리함. 그리고 예외를 처리하고 나면 본래 하던 작업으로 되돌아와 실행을 재개함.
- **예외 유형**:
  - **폴트**: 예외 처리 루틴을 수행한 직후, **예외가 발생한 명령어부터** 다시 실행을 재개하는 예외임. ex) 페이지 폴트
  - **트랩**: 예외 처리 루틴을 끝낸 뒤, 예외가 발생했던 명령어의 **바로 다음 명령어부터** 실행을 이어 나가는 예외임. ex) 디버깅의 브레이크 포인트
  - **중단**: CPU가 더 이상 프로그램을 유지할 수 없을 정도로 **심각하고 중대한 오류**가 발생하여, 프로그램을 강제로 완전히 종료시키는 예외임.
  - **소프트웨어 인터럽트**: 시스템 콜이 발생했을 때 발생하는 예외임.

## CPU 성능 향상을 위한 설계
### CPU 클럭 속도
- **클럭**: 컴퓨터의 부품을 일사불란하게 움직일 수 있게 하는 시간의 단위(`똑-딱-똑-딱`주기)임.
- 초당 클럭 반복 횟수를 나타내는 **헤르츠(Hz)** 를 사용함. 현대 CPU는 1초에 약 10억 번 치는 기가헤르츠(`GHz`) 단위를 표준으로 사용함.
- 클럭 속도를 무리하게 올리면 CPU가 명령어를 더 빠르게 처리하므로 절대적인 성능은 향상되지만, 부품 내 전력 소모가 극심해지고 **발열 문제**가 발생함. 따라서 무작정 클럭만 높이는 데는 물리적 한계가 존재함.

### 멀티코어와 멀티스레드 
- **코어**: CPU 내에서 명령어를 인출하고, 해석하고, 실행하는 하드웨어 부품을 의미함. 과거에는 1 CPU 1 코어였으나 현재는 여러 개의 코어를 포함하고 있는 **멀티코어 CPU**를 많이 씀.
- **스레드**: 실행 흐름의 단위임. 관점에 따라 하드웨어적 관점과 소프트웨어적 관점으로 구분함.

- **하드웨어 스레드**
  - **하나의 물리적인 코어가 동시에 처리할 수 있는 명령어의 단위**를 의미함.
  - 예를 들어, 하나의 코어 내부에 레지스터 세트를 여러 개 두어, 마치 2개의 CPU가 있는 것처럼 동시에 명령어를 처리하는 기술을 **멀티스레드 프로세서**라고 함.
  - 하드웨어 스레드가 2개인 코어가 2개 있다면, 이를 시스템 구조적으로 `2코어 4스레드`라고 부르며 OS 입장에서는 4개의 CPU(논리 프로세서)가 있는 것으로 인식함.
- **소프트웨어 스레드**
  - **하나의 프로그램에서 독립적으로 실행되는 단위**임.
  - 여러 개의 작업을 독립적으로 쪼개어 동시 실행할 때 소프트웨어 스레드를 생성함.

### 병렬성과 동시성
- **병렬성**: 작업을 물리적으로 동시에 처리하는 성질임. 하드웨어 스레드 4개인 CPU가 4개의 명령어를 동시에 실행함.
- **동시성**: 동시에 작업을 처리하는 것처럼 보이는 성질임. CPU가 빠르게 작업을 번갈아 가며 처리해서 사용자 눈에는 여러 작업이 동시에 처리되는 것처럼 보임.
- 하드웨어 스레드는 병렬성을 구현하기 위한 물리적인 실행 단위에 가깝고 소프트웨어 스레드는 동시성을 구현하기 위한 논리적인 실행 단위에 가까움.

## 파이프라이닝을 통한 명령어 병렬 처리
- **명령어 병렬 처리 기법**: 여러 명령어를 동시에 처리하여 CPU를 한시도 쉬지 않고 작동시킴으로써 CPU의 성능을 높이는 기법임.
- **명령어 파이프라이닝**: 명령어 병렬 처리 기법이고, 명령어들을 명령어 파이프라인에 넣고 동시에 처리하는 기법임.
- CPU는 명령어 인출, 명령어 해석, 명령어 실행, 결과 저장의 같은 단계가 겹치지만 않는다면 각각의 단계를 동시에 실행할 수 있음.

### 슈퍼스칼라
- CPU 내부에 **여러 명령어 파이프라인을 포함하는 구조**를 의미함.
- 공장의 생산 라인을 여러 개 두는 것과 같으며, 오늘날 대부분의 현대 CPU는 이 방식을 사용하는 슈퍼스칼라 프로세서임.

### CISC vs RISC
- CISC는 다채로운 기능을 지원하는 복잡한 명령어들로 구성된 명령어 집합임. 그래서 적은 수의 명령어로도 프로그램을 실행할 수 있음.
- RISC는 짧고 규격화된 명령어, 1클럭 내외로 실행되는 명령어를 지향해서 같은 프로그램이더라도 RISC에는 더 많은 명령어가 필요함.
- 이러한 특성 때문에 CISC는 RISC에 비해 명령어의 수행 시간이 길고 들쑥날쑥해서 파이프라이닝에 비효율적임.

### 파이프라인 위험
- **파이프라인 위험**: 파이프라이닝이 실패하여 성능 향상이 이루어지지 않는 상황임. 데이터 위험과 제어 위험, 구조적 위험으로 구분할 수 있음.
- **데이터 위험**: 데이터 의존성에 의해 발생함. 의존성이 있는 두 명령어를 무작정 겹쳐서 실행하면 파이프라인이 제대로 작동하지 않을 수 있음.
- **제어 위험**: 프로그램 카운터의 갑작스러운 변화에 의해 발생함. 프로그램 실행의 흐름이 바뀌어 프로그램 카운터의 갑작스러운 변화가 생기면 인출했거나 해석 중인 명령어들이 쓸모가 없어짐.
- **구조적 위험(=자원 위험)**: 명령어들을 겹쳐 실행하는 과정에서 서로 다른 명령어가 동시에 ALU, 레지스터 등 같은 CPU 부품을 사용하려고 할 때 발생함.
