## 5. 보조기억장치와 입출력장치

### RAID

- **RAID(Redundant Array of Independent Disks)**: **데이터의 안전성** 또는 **성능**을 확보하기 위해 여러 개의 독립적인 보조기억장치를 **하나의 보조기억장치처럼 사용**하는 기술

**RAID 레벨 비교**

| 레벨 | 방식 | 장점 | 단점 |
|---|---|---|---|
| **RAID0** | 데이터를 여러 디스크에 분산 저장 (스트라이핑) | 빠른 입출력 속도 | 하나의 디스크 고장 시 전체 데이터 손실 |
| **RAID1** | 완전한 복사본 생성 (미러링) | 복구 간단함, 안전성 높음 | 쓰기 속도 느림, 사용 가능 용량 적어짐 |
| **RAID4** | 패리티 정보를 전담 디스크에 저장 | RAID1보다 적은 디스크로 안전성 확보 | 패리티 디스크에 병목 현상 발생 |
| **RAID5** | 패리티를 모든 디스크에 분산 저장 | RAID4의 병목 현상 해결 | RAID6보다 안전성 낮음 |
| **RAID6** | 서로 다른 2개의 패리티를 분산 저장 | RAID4, RAID5보다 높은 안전성 | 쓰기 속도 느림 (패리티 2개 저장) |

> **Nested RAID**: 여러 RAID 레벨을 혼합한 방식 (예: RAID10 = RAID0 + RAID1, RAID50 = RAID0 + RAID5)

### 입출력 기법

입출력장치는 CPU와 직접 연결되지 않고, **장치 컨트롤러**를 통해 컴퓨터 내부와 연결됨.

- **장치 컨트롤러**: CPU와 입출력장치 사이의 통신을 중개하는 하드웨어
- **장치 드라이버**: 장치 컨트롤러의 동작을 알고, 컴퓨터 내부와 정보를 주고받을 수 있도록 하는 소프트웨어

**입출력 기법 3가지**

| 기법 | 설명 | 특징 |
|---|---|---|
| **프로그램 입출력** | 프로그램 속 명령어로 입출력 작업 수행 | CPU가 직접 장치 컨트롤러와 상호작용 |
| **인터럽트 기반 입출력** | 하드웨어 인터럽트를 통해 입출력 완료를 통보받음 | 다중 인터럽트 발생 시 우선순위에 따라 처리 (PIC 사용) |
| **DMA 입출력** | CPU를 거치지 않고 입출력장치와 메모리가 직접 데이터를 주고받음 | CPU 부담을 줄임, DMA 컨트롤러 필요함 |

**DMA 입출력 동작 과정**

1. CPU가 DMA 컨트롤러에게 입출력 작업을 명령함.
2. DMA 컨트롤러가 CPU 대신 장치 컨트롤러와 상호작용하며 입출력 작업을 수행함.
3. 작업이 끝나면 DMA 컨트롤러가 CPU에게 인터럽트를 걸어 완료를 알림.

> **사이클 스틸링**: 시스템 버스는 동시 사용이 불가능하므로, DMA 컨트롤러는 CPU가 버스를 사용하지 않을 때마다 조금씩 사용함. CPU 입장에서는 버스 접근 사이클을 도둑맞는 것처럼 느껴짐.

- **PCIe(Peripheral Component Interconnect Express)**: 오늘날 메인 보드에서 가장 대중적인 입출력 버스
  - SSD, GPU, 네트워크 인터페이스 카드 등을 연결함.
  - 버전이 높을수록 최대 속도가 증가함.
  - **레인(lane)**: PCIe 버스를 통해 정보를 송수신하는 단위. 레인 수가 많을수록 대역폭 증가함.
