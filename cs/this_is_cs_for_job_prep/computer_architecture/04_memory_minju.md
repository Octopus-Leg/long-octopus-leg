## 4. 메모리

### RAM

실행 중인 프로그램은 메모리에 저장되며, CPU는 메모리에 저장된 정보를 읽고, 쓰고, 실행함.

- **RAM(Random Access Memory)**: 임의의 위치에 곧장 접근 가능한 **휘발성 저장장치**
  - 전원을 끄면 저장된 데이터가 사라짐.
  - CPU는 보조기억장치의 프로그램을 메모리로 복사한 뒤 실행함.
  - RAM 용량이 클수록 많은 프로그램을 동시에 실행하는 데 유리함.

#### RAM의 종류

| 종류 | 설명 | 특징 |
|---|---|---|
| DRAM | 시간이 지나면 데이터가 사라지는 RAM | 소비 전력이 낮음, 저렴함, 집적도가 높아 메모리로 주로 사용함 |
| SRAM | 시간이 지나도 데이터가 사라지지 않는 RAM | 속도 빠름, 소비 전력이 크고 비쌈, 집적도가 낮음 → 캐시 메모리에 사용함 |
| SDRAM | 클럭 신호와 동기화된 DRAM | 클럭 타이밍에 맞춰 CPU와 정보를 주고받을 수 있음 |
| DDR SDRAM | 대역폭을 두 배로 넓혀 속도를 빠르게 만든 SDRAM | 한 클럭당 두 번씩 CPU와 데이터를 주고받음 (SDR 대비 속도 2배) |

### 메모리에 바이트를 밀어 넣는 순서 - 빅 엔디안과 리틀 엔디안

메모리는 데이터를 바이트 단위로 저장하며, 일반적으로 4바이트(32bit) 또는 8바이트(64bit) 워드 단위로 받아들임.

여러 바이트로 구성된 데이터를 메모리에 저장할 때 **바이트를 어떤 순서로 저장하느냐**에 따라 두 방식으로 나뉨.

| 방식 | 저장 순서 | 장점 |
|---|---|---|
| **빅 엔디안** | 낮은 번지에 **상위(MSB) 바이트**부터 저장 | 메모리 값을 직접 읽기 편함, 디버깅에 편함 |
| **리틀 엔디안** | 낮은 번지에 **하위(LSB) 바이트**부터 저장 | 수치 계산이 편함 (가장 작은 값부터 계산 가능) |

> **예시**: 16진수 `1A2B3C4D`를 메모리 `a+2`번지부터 저장하는 경우
> - 빅 엔디안: `1A` → `2B` → `3C` → `4D`
> - 리틀 엔디안: `4D` → `3C` → `2B` → `1A`

```python
# 컴퓨터 환경의 엔디안 방식 확인 방법
import sys
print(sys.byteorder)  # 'big' 또는 'little' 출력
```

### 캐시 메모리

CPU의 연산 속도와 메모리 접근 속도의 차이를 줄이기 위해 탄생한 **SRAM 기반의 저장장치**.

- CPU가 매번 메모리에 직접 접근하는 대신, 자주 사용할 데이터를 미리 캐시 메모리에 가져와 활용함.

#### 캐시 메모리 계층 구조

- L1 캐시는 **L1I(명령어 전용)** 와 **L1D(데이터 전용)** 로 분리된 **분리형 캐시** 구조를 사용하기도 함.
- 멀티코어 프로세서에서 L1, L2는 코어마다 고유하게 할당되고, L3는 여러 코어가 공유함.

#### 캐시 히트와 캐시 미스

| 용어 | 설명 |
|---|---|
| **캐시 히트** | 캐시 메모리에 예측 저장한 데이터가 실제로 사용되는 경우 |
| **캐시 미스** | 틀린 예측으로 CPU가 메모리에서 직접 데이터를 가져와야 하는 경우 |
| **캐시 적중률** | `캐시 히트 횟수 / (캐시 히트 횟수 + 캐시 미스 횟수)` / 일반적으로 85~95% 이상 |

#### 참조 지역성의 원리

캐시 메모리는 **참조 지역성의 원리**에 따라 메모리에서 가져올 데이터를 결정함.

- **시간 지역성**: CPU는 최근에 접근했던 메모리 공간에 다시 접근하려는 경향이 있음. (예: 변수)
- **공간 지역성**: CPU는 접근한 메모리 공간의 근처에 접근하려는 경향이 있음. (예: 배열)

```python
# 공간 지역성을 고려한 코드
for i in range(20000):
    for j in range(20000):
        matrix[i][j] = 1  # 메모리에 순차적으로 접근

# 공간 지역성을 고려하지 않은 코드
for i in range(20000):
    for j in range(20000):
        matrix[j][i] = 1  # 메모리에 비순차적으로 접근
```

#### 캐시 메모리의 쓰기 정책과 일관성

CPU가 캐시 메모리에 데이터를 쓸 때, 메모리와의 일관성을 유지하기 위한 두 가지 정책이 있음.

| 정책 | 설명 | 장점 | 단점 |
|---|---|---|---|
| **즉시 쓰기 (Write-Through)** | 캐시와 메모리에 동시에 씀 | 일관성 항상 유지 | 매번 메모리 접근 → 버스 사용 시간 증가 |
| **지연 쓰기 (Write-Back)** | 캐시에만 쓰고, 나중에 메모리에 반영 | 메모리 접근 횟수 감소 → 빠름 | 캐시-메모리 간 일관성 깨질 수 있음 |

> 캐싱은 **자주 사용할 법한 대상을 가까이 위치시켜 성능 향상을 꾀하되, 데이터 일관성 유지에 대한 책임이 따름.**
