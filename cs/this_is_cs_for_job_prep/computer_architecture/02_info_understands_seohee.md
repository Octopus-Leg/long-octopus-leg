# 2.2 컴퓨터가 이해하는 정보

- CPU는 0과 1만 이해할 수 있음. 0과 1을 나타내는 가장 작은 정보의 단위를 **비트**라고 함.
- 1비트는 0 또는 1로 2개의 정보를 표현할 수 있고, 2비트는 $2^2$의 정보를, 3비트는 $2^3$을 표현할 수 있음. ➡️ N비트는 $2^N$의 정보를 표현할 수 있음.
- 바이트는 8비트를 묶은 단위를 말하므로 하나의 바이트를 표현할 수 있는 정보는 $2^8=256$개임.
- 킬로바이트(KB), 메가바이트(MB), 기가바이트(GB), 테라바이트(TB)는 모두 이전 단위를 1000개를 묶은 단위를 말함.
- 비트, 바이트, 킬로바이트는 프로그램의 크기를 나타낼 때 사용하는 정보 단위이고, CPU 관점에서의 정보 단위로는 **워드**가 있음.
- **워드**: CPU가 한 번에 처리할 수 있는 데이터의 크기로 CPU가 한 번에 16비트를 처리할 수 있다면 1워드는 16비트가 됨.
- CPU마다 워드의 크기가 다르지만, 현대 컴퓨터의 대부분의 워드 크기는 32비트, 64비트임.

## 데이터 - 0과 1로 숫자 표현하기
### 2진법
- CPU는 컴퓨터 내부에서 2진법을 사용하고, 2진법은 숫자 1을 넘어가는 시점에 자리올림해 0과 1, 2개만으로 모든 수를 표현하는 방식임.
- 2진수를 표현하는 수는 숫자 뒤에 아래첨자로 `(2)`를 붙이거나 2진수 앞에 `0b`를 붙임.
> 컴퓨터에서는 16진법도 주로 사용하는데 이 방식은 숫자 15가 넘어가는 시점에 자리올림을 하는 방식임. 아래첨자로 `(16)`을 붙이거나 숫자 앞에 `0x`를 붙임.
### 부동소수점
- 부동 소수점은 소수점이 고정되어 있지 않은 소수 표현 방식으로, 필요에 따라 소수점의 위치가 이동할 수 있고 유동적이라는 의미를 가짐.
- 10진수 $123.123$을 $1.23123 * 10^2$로 표현할 수도, $1231.23 * 10^{-1}$로도 표현할 수 있음. 이때 지수는 2와 -1 이고, 가수는 1.23123와 1231.23임.
- 마찬가지로 2진수 $1101011.1010$도 $1.1010111010 * 2^6$으로 표현할 수도, $110101110.10 * 2^{-2}$로도 표현할 수 있음.
- 즉, 2의 지수가 양수일 때는 소수점을 왼쪽으로 이동한 횟수, 음수일 때는 소수점을 오른쪽으로 이동한 횟수라고 생각해도 됨.

### IEEE 754 부동 소수점 표현 방식
- 오늘날 대부분의 컴퓨터가 2진수 지수와 가수를 저장하는 국제 표준 방식임.
- 구조는 크게 **부호 비트**, **지수 비트**, **가수 비트** 3가지 체계로 나뉨.
  - **32비트 / float:** 부호(1비트) + 지수(8비트) + 가수(23비트)
  - **64비트 / double:** 부호(1비트) + 지수(11비트) + 가수(52비트)
  - 부호 비트는 0이면 양수, 1이면 음수를 의미함.

- **가수의 정규화**
  - 컴퓨터는 가수를 저장할 때 항상 정수부가 `1`인 $1.XXXX...$ 형태로 통일하여 저장함.
  - 어차피 정수부는 무조건 `1`로 고정이므로, 컴퓨터는 **메모리를 아끼기 위해 정수 1을 제외한 소수점 아래 부분($XXXX...$)만 가수 비트에 저장**함.
- **지수의 바이어스 표현:**
  - 지수 비트에는 음수 지수도 표현할 수 있도록 일정한 가산수를 더해서 저장함.
  - 32비트 형식의 바이어스는 **127**이며, 실제 지수가 $6$이라면 $127 + 6 = 133$(2진수로 변환)을 지수 영역에 저장함.

### 부동 소수점 오차가 발생하는 원인
- 10진수 소수를 2진수 소수로 바꿀 때 **딱 맞아떨어지지 않고 무한 소수가 되는 경우가 존재**하기 때문임.
- 컴퓨터의 저장 공간은 한정되어 있으므로, 무한히 이어지는 소수점을 모두 저장하지 못하고 **일부 뒷자리를 잘라내어 가장 가까운 값으로 근사치 저장을 함.** 이 과정에서 미세한 미스매치가 누적되어 `Not Equal`과 같은 연산 오차가 발생함.

## 데이터 - 0과 1로 문자 표현하기
- 컴퓨터가 이해할 수 있는 문자들의 집합을 **문자 집합**이라고 함.
- 문자 집합에 속한 문자를 컴퓨터가 이해하는 0과 1로 이루어진 문자 코드로 변환하는 과정을 **문자 인코딩**이라고 함.
- 반대로 0과 1로 표현된 문자를 사람이 이해하는 문자로 변환하는 과정을 **문자 디코딩**이라고 함.

### 아스키
- 가장 기본적인 문자 집합로, 영어의 알파벳과 아라비아 숫자, 일부 특수 문자를 포함함.
- 아스키 문자를 표현하기 위해서는 8비트를 사용함.
- 8비트 중 1비트는 패리티 비트라고 불리는데 이는 오류 검출에 사용되는 비트여서 문자 표현을 위해 사용하는 비트는 7비트임. ➡️ 128개의 문자 표현이 가능함.
- 아스키 문자들은 0부터 127까지의 숫자 중 하나의 고유한 수에 대응됨.

### EUC-KR
- 아스키 코드는 한글을 표기할 수 없어서 한글 인코딩 방식 중 하나가 EUC-KR임.
- 아스키 코드를 표현할 때는 1바이트, 하나의 한글 글자를 표현할 떄는 2바이트 크기의 코드를 부여함.
- 2바이트는 네 자리 16진수로 표현할 수 있으므로 EUC-KR로 인코딩된 한글 글자 하나는 네 자리 16진수로 나타낼 수 있음. ex) `0xb1db`

### 유니코드
- EUC-KR만으로는 모든 한글 조합을 표현할 수 없어서 등장한 것이 유니코드임.
- 많은 언어, 특수문자, 화살표, 이모티콘까지 코드로 표현할 수 있는 통일된 문자 집합으로 현대 가장 많이 사용되는 표준 문자 집합임.
- 유니코드는 글자에 부여된 값 자체를 인코딩된 값으로 삼지 않고, 이 값을 `UTF-8`, `UTF-16`, `UTF-32` 등으로 인코딩함.
- `UTF-8`, `UTF-16`, `UTF-32`는 가변 길이 인코딩 방식이라 인코딩된 결과의 길이가 일정하지 않을 수 있음.

### base64 인코딩
- 비단 문자뿐만 아니라 이진 데이터까지 변환할 수 있는 인코딩 방식임. 특히 이진 데이터를 인코딩하는 데 더 많이 사용됨.
- base64 인코딩은 이미지 등 문자 이외의 데이터까지 아스키 문자 형태로 표현할 수 있음.
- base64는 64진법을 의미하고, 하나의 인코딩 값을 사용하기 위해 64개의 문자가 사용됨. ➡️ $64=2^6$의 지수인 6비트가 필요함.
- 기본적으로 4개(24비트)씩 한 번에 변환됨. 6비트씩 나누어 떨어지지 않을 때는 나누어 떨어지지 않는 자리가 0으로 채워지는 **패딩**이 되고 `=`로 인코딩됨.

## 명령어
- **연산 코드**: 명령어가 수행할 동작
- **오퍼랜드**: 동작에 사용할 데이터 혹은 동작에 사용될 데이터가 저장된 위치
- 하나의 명령어는 연산 코드와 0개 이상의 오퍼랜드로 구성되어 있음. 명령어에서 연산 코드가 담기는 영역은 연산 코드 필드, 오퍼랜드가 담기는 영역은 오퍼랜드 필드라고 함.
- 오퍼랜드 필드에는 연산 코드에 사용될 데이터가 저장된 위치가 주로 명시되어서 오퍼랜드 필드를 주소 필드라고도 부름.

### 기계어와 어셈블리어
- 기계어: CPU가 이해할 수 있도록 0과 1로 표현된 정보를 있는 그대로 표현한 언어
- 어셈블리어: 0과 1로 표현된 기계어를 읽기 편한 형태로 단순 번역한 언어
  - 어셈블리어 예시
    ```text
    push rbp
    mov rbp, rsp
    mov DWORD PTR [rbp-4], edi
    mov eax, DWORD PTR [rbp-4]
    imul eax, eax
    pop rbp
    ret
    ```
    - CPU마다 어셈블리어가 다르게 표현될 수 있어서 특정 CPU에만 의존적인 코드를 만들지 말아야 함.

### 명령어 사이클
- 인출 사이클: 명령어 사이클의 첫 번째 과정으로, 메모리에 있는 명령어를 CPU로 가지고 오는 단계를 말함.
- 실행 사이클: 명령어 사이클의 두 번째 과정으로 CPU로 가져온 명령어를 실행하는 단계를 말함.
- 간접 사이클: 오퍼랜드 필드에 메모리 주소가 명시된 경우처럼 명령어를 실행하기 위해 한 번 더 메모리에 접근하는 단계를 말함.
- 인터럽트 사이클: 인터럽트를 처리하는 단계를 말함.
- 어떤 명령어는 인출, 실행 사이클만으로 실행되고, 어떤 명령어는 인출, 간접, 실행 사이클을 모두 거쳐 실행됨.
