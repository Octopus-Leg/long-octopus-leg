## 3. CPU

### 레지스터

- 레지스터는 CPU 내부의 작은 임시 저장장치임.
- 프로그램의 데이터와 명령어가 실행 전후로 레지스터에 저장되므로, 레지스터 값만 봐도 프로그램 동작을 파악할 수 있음.
- WinDbg(Windows), gdb(Linux, macOS) 등의 디버깅 도구로 관찰 가능함.

**대표 레지스터**

- **프로그램 카운터(PC)**: 다음으로 읽어 들일 명령어의 주소를 저장하는 레지스터 (= IP)
- **명령어 레지스터(IR)**: 방금 읽어 들인, 해석할 명령어를 저장하는 레지스터
- **범용 레지스터**: 데이터, 명령어, 주소를 자유롭게 저장하는 레지스터
- **플래그 레지스터**: 연산 결과나 CPU 상태에 대한 부가 정보를 저장하는 레지스터
- **스택 포인터**: 메모리 내 스택 영역의 최상단 데이터 위치를 가리키는 레지스터

**플래그 종류**

- **부호 플래그**: 연산 결과의 부호
- **제로 플래그**: 연산 결과가 0인지 여부
- **캐리 플래그**: 올림수나 빌림수의 발생 여부
- **오버플로우 플래그**: 오버플로우 발생 여부
- **인터럽트 플래그**: 인터럽트 가능 여부
- **슈퍼바이저 플래그**: 커널 모드인지 사용자 모드인지 여부

### 인터럽트

- **인터럽트(interrupt)**: CPU의 작업을 방해하는 신호

```
인터럽트 (Interrupt)
│
├── 동기 인터럽트 (예외) - CPU에 의해 발생
│   │
│   ├── 폴트(Fault): 예외 발생 명령어부터 재개
│   ├── 트랩(Trap): 예외 발생 명령어 다음부터 재개
│   ├── 중단(Abort): 심각한 오류 → 프로그램 강제 중단
│   └── 소프트웨어 인터럽트: 시스템 콜 발생 시
│
└── 비동기 인터럽트 (하드웨어) - 입출력장치에 의해 발생
    │
    ├── 막을 수 있는 인터럽트 (Maskable)
    └── 막을 수 없는 인터럽트 (NMI)
```

- 하드웨어 인터럽트를 사용하면 입출력장치의 작업 완료 여부를 주기적으로 확인하는 **폴링(polling)** 보다 효율적임.

**CPU의 하드웨어 인터럽트 처리 순서**

1. 입출력장치가 CPU에게 **인터럽트 요청 신호**를 보냄.
2. CPU는 실행 사이클이 끝나고 명령어 인출 전에 인터럽트 여부를 확인함.
3. **인터럽트 플래그**를 통해 인터럽트 수용 가능 여부를 확인함.
4. 수용 가능하면 지금까지의 작업을 **스택에 백업**함.
5. **인터럽트 벡터**를 참조해 **인터럽트 서비스 루틴(ISR)** 을 실행함.
6. ISR 실행이 끝나면 백업한 작업을 복구해 실행을 재개함.

**핵심 용어**

- **인터럽트 요청 신호**: 입출력장치가 CPU에 보내는 인터럽트 가능 여부 확인 신호
- **인터럽트 플래그**: 하드웨어 인터럽트 수용 여부를 결정하는 플래그
- **인터럽트 벡터**: ISR을 식별하기 위한 정보로 ISR의 시작 주소를 포함함
- **인터럽트 서비스 루틴(ISR)**: 인터럽트 처리 프로그램으로 인터럽트 핸들러라고도 부름

### CPU 성능 향상을 위한 설계

**① 클럭**

- **클럭(clock)**: 컴퓨터의 부품을 일사불란하게 움직이게 하는 시간 단위로 헤르츠(Hz) 단위로 측정됨
- 클럭 속도가 높으면 일반적으로 CPU 성능이 좋음. 단, 필요 이상 높이면 **발열**이 심해져 한계가 있음.

**② 멀티코어와 멀티스레드**

- **코어(core)**: CPU 내에서 명령어를 읽고, 해석하고, 실행하는 부품
- **멀티코어 CPU**: 코어를 여러 개 포함하는 CPU
- **하드웨어 스레드**: 하나의 코어가 동시에 처리하는 명령어 단위로 **논리 프로세서**라고도 부름.
- **소프트웨어 스레드**: 하나의 프로그램에서 독립적으로 실행되는 단위로 하드웨어 스레드가 1개여도 여러 개 실행 가능함.

> **동시성과 병렬성**
> - **병렬성(parallelism)**: 작업을 **물리적으로** 동시에 처리하는 성질로 하드웨어 스레드의 특성
> - **동시성(concurrency)**: 동시에 처리하는 것**처럼 보이게** 처리하는 성질로 소프트웨어 스레드의 특성

### 파이프라이닝을 통한 명령어 병렬 처리

- **명령어 병렬 처리 기법(ILP)** 의 핵심 기술임. 처리 단계가 겹치지 않는다면 각 단계를 동시에 실행할 수 있음.

명령어 처리는 다음 4단계로 나뉨.

1. 명령어 인출(Instruction Fetch)
2. 명령어 해석(Instruction Decode)
3. 명령어 실행(Execute Instruction)
4. 결과 저장(Write Back)

- **슈퍼스칼라(superscalar)**: CPU 내부에 여러 개의 명령어 파이프라인을 포함하는 구조

**파이프라인 위험(pipeline hazard)**

- **데이터 위험**: 명령어 간 데이터 의존성으로 발생함. 이전 명령어가 끝나야만 실행 가능한 경우
- **제어 위험**: JUMP, 인터럽트 등 프로그램 카운터의 갑작스러운 변화로 발생함.
- **구조적 위험**: 서로 다른 명령어가 동시에 ALU, 레지스터 같은 부품을 사용할 때 발생함. (= 자원 위험)

**CISC와 RISC**

- **CISC(Complex Instruction Set Computer)**: 복잡하고 다채로운 명령어로 구성됨. 적은 수의 명령어로 프로그램을 실행할 수 있음. 명령어 크기와 실행 시간이 일정하지 않아 파이프라이닝에 비효율적임. 대표 CPU는 인텔 x86, x86-64임.
- **RISC(Reduced Instruction Set Computer)**: 짧고 규격화된 명령어로 구성됨. 1클럭 내외로 실행되어 파이프라이닝에 최적화됨. 같은 프로그램이라도 CISC보다 많은 명령어가 필요함. 대표 CPU는 애플 M1임.
