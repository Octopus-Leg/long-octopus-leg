# 4.4 해시 테이블

## 해시 테이블
- **키와 값**의 대응으로 이루어진 표(테이블) 형태의 자료구조임.
- 대표적인 예시로 전화번호부(이름-전화번호), 책(ISBN-책 제목) 등이 있음.
- **구조와 동작**:
  - 데이터가 저장되는 공간을 **버킷**이라고 하며, 여러 버킷이 모여 배열을 형성함.
  - `해시 함수`를 통해 키를 인덱스로 변환하고, 이 인덱스를 사용하여 버킷 배열에 즉각적으로 접근함.
- **로드 팩터(Load Factor)**: 해시 테이블에 저장된 데이터 수를 버킷의 수로 나눈 값임. 로드 팩터가 클수록 해시 테이블이 많이 차 있다는 뜻이며, 이 값이 커질수록 성능이 떨어짐.

## 해시 함수
- 임의의 길이를 가진 데이터를 고정된 길이의 데이터(해시 값)로 변환하는 **단방향 함수**임. 역산하여 원래 데이터를 도출하기는 매우 어려움.
- **해시 알고리즘**: MD5, SHA-1, SHA-256, SHA-512, SHA3, HMAC 등이 대표적인 해시 알고리즘임. 해시 알고리즘이 다르면 도출되는 해시 값이나 길이가 다름.
- 데이터 무작위화, 단방향 암호 생성, **데이터 무결성 검증** 등에 활용됨.
- 글자 하나만 달라져도 완전히 다른 해시 값이 도출되므로 데이터의 왜곡이나 훼손 여부를 쉽게 파악할 수 있음.
- 비밀번호 암호화용 함수로는 `bcrypt`, `PBKDF2`, `scrypt`, `argon2` 등이 쓰임.
- **해시 테이블의 장점**: 탐색, 삽입, 삭제 연산의 시간 복잡도가 $O(1)$로 **매우 빠른 검색 속도**를 자랑함. 입력 크기와 무관하게 항상 일정한 속도를 보장함.
- **해시 테이블의 단점**: 속도가 빠른 만큼 상대적으로 **많은 메모리 공간이 소요**됨. 데이터가 많을 경우 공간 복잡도가 증가함.

## 해시 충돌
- 서로 다른 키에 대해 **동일한 해시 값이 도출**되어 같은 버킷을 가리키는 상황을 말함.

### 해시 충돌 해결 방법

#### 1. 체이닝
- 충돌이 발생한 데이터를 **연결 리스트로 연결**하여 추가하는 방식임.
- 구조가 단순하고 구현이 쉽지만, 충돌이 빈번하여 $n$개의 데이터가 모두 충돌하면 연결 리스트를 탐색해야 하므로 성능이 `$O(n)$`으로 저하됨.

#### 2. 개방 주소법
- 충돌이 발생했을 때 빈 버킷을 찾아 다른 인덱스에 데이터를 저장하는 방법임. ➡️ 비어 있는 다른 버킷의 인덱스를 찾는 과정을 **조사**라고 말함.
- **선형 조사법**: 충돌 발생 시 다음 인덱스부터 `f(key) + 1, f(key) + 2` 순으로 빈 자리를 순차적으로 탐색함. 충돌된 데이터들이 특정 인덱스 주변에 뭉치는 **데이터 군집화** 현상이 발생하여 성능이 저하될 수 있음.
- **이차 조사법**: 선형 조사법의 문제인 군집화 현상을 완화하기 위해 제곱수만큼 떨어진 거리(`f(key) + 1^2, f(key) + 2^2, f(key) + 3^2...`)의 인덱스를 탐색함.
- **이중 해싱**: 2개의 해시 함수를 사용하여 충돌 시 보조 해시 함수의 값만큼 떨어진 거리를 탐색함. 인덱스가 규칙적이지 않고 무작위로 생성되므로 선형 조사법의 군집화 문제를 상당 부분 회피할 수 있음.
  - `f(key) + g(key), f(key) + 2g(key)` 순으로 인덱스를 찾음.

## 프로그래밍 언어별 해시 테이블 구현
- 각 언어에서는 해시 테이블을 다음과 같은 기본 자료구조로 지원함.

| 프로그래밍 언어 | 구현체 이름 |
| :--- | :--- |
| **C++** | `unordered_map` |
| **자바 (Java)** | `HashTable`, `HashMap` |
| **파이썬 (Python)** | `dictionary` |
| **자바스크립트 (JavaScript)** | `Map` |
| **Go** | `map` |
