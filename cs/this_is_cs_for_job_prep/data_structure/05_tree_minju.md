## 5. 트리

- **트리(tree)**: 주로 계층적인 구조를 표현하기 위한 자료구조. 데이터가 저장된 **노드(node)** 와 노드를 연결하는 **간선(edge, 링크)** 으로 이루어지며, 간선으로 연결된 노드는 상하 관계를 형성함.

| 용어 | 설명 |
|---|---|
| 노드 | 트리에서 데이터를 저장하는 구성 요소 |
| 간선 | 노드를 연결하는 구성 요소 |
| 부모 노드(parent node) | 어떤 노드의 상위에 연결된 노드 |
| 자식 노드(child node) | 어떤 노드의 하위에 연결된 노드 |
| 루트 노드(root node) | 트리의 최상위 노드, 부모 노드가 없는 노드 |
| 리프 노드(leaf node) | 트리의 최하위 노드, 자식 노드가 없는 노드 |
| 차수(degree) | 어떤 노드가 가지고 있는 자식 노드의 수 |
| 레벨(level) | 루트 노드에서 특정 노드에 이르기까지 거치는 간선의 수 |
| 서브트리(subtree) | 트리에 포함되어 있는 부분 트리 |

> 같은 부모를 공유하는 노드는 **형제 노드(sibling node)**, 부모와 그 부모들은 **조상 노드(ancestor node)**, 자식과 그 자식들은 **자손 노드(descendant node)** 라고 함. 특정 노드가 얼마나 깊은 곳에 있는지를 뜻하는 **깊이(depth)** 는 레벨과 같은 개념이며, 가장 높은 레벨이 트리의 **높이(height)** 가 됨.

### 트리의 순회

- **트리의 순회(tree traversal)**: 트리의 모든 노드를 한 번씩 방문하는 것. 기술 면접이나 코딩 테스트에서 자주 언급됨.

| 순회 방법 | 방문 순서 |
|---|---|
| **전위 순회(preorder)** | 루트 노드 → 왼쪽 서브트리 전위 순회 → 오른쪽 서브트리 전위 순회 |
| **중위 순회(inorder)** | 왼쪽 서브트리 중위 순회 → 루트 노드 → 오른쪽 서브트리 중위 순회 |
| **후위 순회(postorder)** | 왼쪽 서브트리 후위 순회 → 오른쪽 서브트리 후위 순회 → 루트 노드 |

각 순회는 재귀 함수로 간단히 구현할 수 있음. 전위 순회의 의사 코드는 다음과 같음.

```
전위 순회(노드):
    if 노드가 존재하지 않으면:
        return
    노드 값 출력
    전위 순회(노드의 왼쪽 자식)
    전위 순회(노드의 오른쪽 자식)
```

> **레벨 순서 순회(level-order traversal)**: 가장 낮은 레벨부터 차례로 노드를 순회하는 방법.

### 트리의 종류

#### ① 이진 트리(binary tree)

자식 노드의 개수가 2개 이하인 트리. '트리' 하면 가장 먼저 떠올릴 만한 대중적인 트리임.

- **편향된 이진 트리(skewed binary tree)**: 모든 자식 노드가 한 쪽으로 치우친 이진 트리.
- **정 이진 트리(full binary tree)**: 자식 노드의 개수가 0개 또는 2개인 이진 트리.
- **포화 이진 트리(perfect binary tree)**: 리프 노드를 제외한 모든 노드가 자식 노드를 2개씩 가지고, 모든 리프 노드의 레벨이 동일한 이진 트리.
- **완전 이진 트리(complete binary tree)**: 마지막 레벨을 제외한 모든 레벨이 2개의 자식 노드를 가지며, 마지막 레벨의 노드들이 왼쪽부터 채워진 이진 트리.

#### ② 탐색에 활용되는 트리

- **이진 탐색 트리(BST, Binary Search Tree)**: 특정 노드의 왼쪽 서브트리에는 작은 값, 오른쪽 서브트리에는 큰 값을 지닌 노드들이 있는 이진 트리. `O(log n)`으로 원하는 값을 탐색할 수 있음. 단, 모든 노드가 일렬로 구성된 편향된 이진 트리에서는 탐색 속도가 `O(n)`이 됨(최악의 상황).
- **힙(heap)**: 완전 이진 트리의 종류 중 하나로, 최댓값과 최솟값을 빠르게 찾기 위해 사용됨. 탐색에 일반적으로 `O(log n)`이 소요됨. **최대 힙**은 부모 노드가 자식 노드의 값보다 큰 값, **최소 힙**은 부모 노드가 자식 노드의 값보다 작은 값으로 이루어짐. 최대 힙으로 우선순위 큐를 구현할 수 있음.

#### ③ 균형을 맞추는 트리: RB 트리

이진 탐색 트리는 삽입·삭제를 반복하는 과정에서 편향된 트리가 될 수 있고, 이 경우 탐색 속도가 `O(n)`으로 떨어짐. 이를 방지하기 위해 왼쪽/오른쪽 서브트리 높이의 균형을 맞추는 **자가 균형 이진 탐색 트리(self-balancing binary search tree)** 가 있으며, **AVL 트리(Adelson-Velsky and Landis Tree)** 와 **RB 트리(Red Black Tree)** 가 대표적임.

RB 트리는 **노드에 색을 칠하는 규칙**과 **노드에 칠해진 색**을 기준으로 균형을 맞춤. 노드는 블랙 또는 레드로 칠하며, 유지 조건은 다음과 같음.
1. 루트 노드는 블랙 노드이다.
2. 리프 노드는 블랙 노드이다.
3. 레드 노드의 자식 노드는 블랙 노드이다.
4. 루트 노드에서 임의의 리프 노드에 이르는 경로의 블랙 노드 수는 같다.

> RB 트리의 리프 노드는 실질적인 데이터가 없는 **NIL(Null Leaf) 노드**로 가정함. 새 노드는 (루트가 아닌 이상) 레드로 간주해 일반 이진 탐색 트리처럼 삽입한 뒤, 조건에 부합하지 않으면 **트리를 회전**하거나 **색상을 재지정**함. 트리의 회전이란 부모 노드와 자식 노드의 관계를 재지정하는 것으로, 왼쪽 또는 오른쪽 방향으로 이루어짐.

> RB 트리는 리눅스의 CPU 스케줄러인 CFS 스케줄러, 프로그래밍 언어 내부 구현(예: C++ `std::map`) 등 컴퓨터 과학 전반에 녹아 있는 근원적인 자료구조임.

#### ④ 대용량 입출력을 위한 트리: B 트리

RB 트리처럼 균형을 유지하지만, 이진 탐색 트리가 아닌 **다진 탐색 트리**의 한 종류임. 한 노드가 여러 자식 노드를 가질 수 있음.

- 한 노드가 가질 수 있는 최대 자식 노드의 개수가 M개인 B 트리를 **M차 B 트리**라고 함. (루트·리프를 제외하고) 가질 수 있는 최소 자식 노드의 개수는 `⌈M/2⌉`개임.
- 각 노드에는 하나 이상의 **키(key)** 값이 **오름차순**으로 저장됨. 키가 N개인 노드가 가질 수 있는 자식 노드의 수는 반드시 `(N + 1)`개임.
- 모든 리프 노드의 깊이가 같아 편향된 형태가 발생하지 않음.
B 트리는 파일 시스템, 데이터베이스처럼 대량의 데이터를 다룰 때 활용됨. 블록 단위로 보조기억장치를 읽고 쓰는 환경에서, 한 노드에 블록 단위의 여러 데이터를 저장할 수 있어 입출력 연산 횟수를 줄여 성능상 이득임.

> **B+ 트리**: 오늘날 파일 시스템·데이터베이스에서 자주 쓰이는 변형. 실질적 데이터가 모두 최하위 리프 노드에 위치하고, 최하위 리프 노드가 연결 리스트 형태를 띠어 범위 연산이 용이함.
> <br>이 밖에 **트라이(trie)**, **세그먼트 트리(segment tree)**, **펜윅 트리(fenwick tree)** 등 다양한 트리가 있음.
