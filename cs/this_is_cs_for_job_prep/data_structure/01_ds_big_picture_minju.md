## 1. 자료구조의 큰 그림

### 자료구조와 알고리즘

- **자료구조(data structure)**: 어떠한 구조로 데이터를 다룰지에 대해 학습하는 과목. 메모리 내 스택 영역의 '스택'과 스케줄링 큐의 '큐'도 자료구조의 일종임.
- **알고리즘(algorithm)**: 어떤 목적을 이루기 위해 필요한 일련의 연산 절차.
- 자료구조가 데이터를 효율적으로 저장하고 관리하기 위한 방법을 다룬다면, 알고리즘은 어떤 목적을 이루기 위한 효율적인 연산 방법을 다룸. 어떤 자료구조가 사용되었느냐에 따라 사용 가능한 알고리즘이 달라질 수 있음.

> 너비 우선 탐색과 깊이 우선 탐색은 그래프, 스택 등의 자료구조를 알아야만 온전히 이해할 수 있음.

### 시간 복잡도와 공간 복잡도

시간 복잡도와 공간 복잡도는 소스 코드나 프로그램이 얼마나 효율적인지를 판단하는 척도임.

- **시간 복잡도(time complexity)**: 입력의 크기에 따른 프로그램 실행 시간의 관계. 실행 시간은 연산 횟수에 비례한다고 간주하므로, 입력의 크기에 따른 **연산 횟수**라고도 볼 수 있음.

> 프로그램의 시간 복잡도에 가장 많은 영향을 끼치는 문법은 **반복문**임.

같은 입력이라도 실행 시간은 달라질 수 있어 **최선의 경우**, **최악의 경우**, **평균적인 경우**로 나뉨. 들쑥날쑥한 실행 시간은 척도가 될 수 없으므로 대중적으로 빅 오 표기법을 사용함.

- **빅 오 표기법(big O notation)**: 함수의 **점근적 상한**을 표기하는 방법. 입력 n이 무한대로 커지더라도 실행 시간이 대략 이 이상으로는 커지지 않음을 의미함. 예) `O(n²)`은 n이 증가하더라도 실행 시간의 증가율이 n²보다 **작다**는 것을 표현함.
- **빅 세타 표기법(big θ notation)**: 입력에 대한 '평균적인 실행 시간'. 예) `θ(n²)`은 실행 시간의 증가율이 n²과 **같다**는 것을 의미함.
- **빅 오메가 표기법(big Ω notation)**: 입력에 대한 실행 시간의 **점근적 하한**. 예) `Ω(n²)`은 실행 시간의 증가율이 n²보다 **크다**는 것을 의미함.

> **수식으로 보는 정의**
> - 빅 오: 모든 x ≥ x₀에 대해 f(x) ≤ cg(x)를 만족하는 양의 상수 c와 x₀가 존재할 경우, O(g(x)) = f(x)
> - 빅 세타: f(x) = O(g(x))와 f(x) = Ω(g(x))가 모두 성립할 경우, θ(g(x)) = f(x)
> - 빅 오메가: 모든 x ≥ x₀에 대해 f(x) ≥ cg(x)를 만족하는 양의 상수 c와 x₀가 존재할 경우, Ω(g(x)) = f(x)

- 빅 오 표기 시에는 **최고차항의 차수만** 고려함. n이 무한대로 커지면 계수와 낮은 차수의 항이 끼치는 영향은 무시할 수 있기 때문임. 따라서 연산 횟수 `(n² + 3n + 2)`는 `O(n²)`으로 표기함.
- 대표적인 시간 복잡도는 성능이 좋은 순서대로 O(1) < O(log n) < O(n) < O(n log n) < O(n²) < O(2ⁿ) < O(n!) 와 같음.
  | 정렬 알고리즘 | 시간 복잡도 |
  |---|---|
  | 삽입 정렬 | O(n²) |
  | 선택 정렬 | O(n²) |
  | 버블 정렬 | O(n²) |
  | 병합 정렬 | O(n log n) |
  | 퀵 정렬 | O(n log n) |
  | 힙 정렬 | O(n log n) |

- **공간 복잡도(space complexity)**: 프로그램이 실행되었을 때 필요한 메모리 자원의 양. 입력에 따른 메모리 사용량의 척도이며, 빅 오 표기법으로 입력에 따라 필요한 메모리 자원의 양에 대한 점근적 상한을 표현함.

> 오늘날 알고리즘 성능 판단에는 주로 시간 복잡도가 사용되므로, 특별한 언급이 없는 한 빅 오 표기법으로 표현된 성능은 시간 복잡도를 의미함.
