# 5.3 네트워크 계층 - IP

## IP의 목적과 특징
- **IP**: 물리 계층과 데이터 링크 계층 기술이 주로 LAN을 위한 것이라면, LAN을 넘어 다른 네트워크와 통신을 주고받기 위해 필요한 네트워크 계층의 가장 핵심적인 프로토콜임.
- **목적**: 크게 **주소 지정**과 **단편화** 2가지로 나뉨.
  - **주소 지정**: 네트워크 간 통신 과정에서 호스트를 특정하는 것을 의미함.
  - **단편화**: 데이터를 여러 IP 패킷으로 올바르게 쪼개어 보내는 것을 의미함.
- **특징**:
  - 신뢰할 수 없는 통신
  - 비연결형 통신

### 주소 지정과 단편화
#### 1. 주소 지정
- **주소 지정 방법**: IP 패킷 헤더의 **송신지 IP 주소**와 **수신지 IP 주소** 필드에 송수신지를 식별할 수 있는 IP 주소를 명시하여 이루어짐.
- **IP 주소 표기와 옥텟**:
  - 하나의 IP 주소는 총 4바이트(32비트) 크기이며, 숫자당 8비트로 표현되므로 `0~255` 범위의 10진수 4개로 표기됨.
  - 이때 점(`.`)으로 구분된 각각의 10진수를 **옥텟**이라고 부름. (예: `192.168.0.1`에서 `192`, `168`, `0`, `1` 각각이 8비트로 표현 가능한 옥텟임)
- **라우터와 라우팅**:
  - 패킷 송수신 시에는 MAC 주소보다 **IP 주소가 우선적으로 활용됨**.
  - 서로 다른 네트워크에 속한 호스트 간 통신 시, IP 주소를 바탕으로 목적지까지 패킷을 전달하는 핵심 장비가 **라우터**임.
  - 전달받은 패킷을 전달할 최적의 경로를 결정하고 해당 경로로 보내주는 과정을 **라우팅**이라고 함.

#### 2. 단편화
- **MTU(Maximum Transmission Unit)**: IP 패킷(헤더+페이로드)이 한 번에 전송될 수 있는 최대 전송 단위를 의미함.
  - 일반적인 MTU 크기는 **1500바이트**임.
  - 전송하려는 패킷 크기가 MTU보다 크면 여러 패킷으로 쪼개서 전송하고 수신지에서 재조합함.
- **IP 패킷 헤더의 단편화 관련 필드**:
  1. **식별자**: 특정 패킷이 어떤 데이터에서 쪼개진 것인지 식별하기 위한 필드임. 같은 정보에서 쪼개진 패킷들은 동일한 식별자를 공유함.
  2. **플래그**: 3비트로 구성되며, 첫 비트(항상 0) 제외 후 두 비트는 각각 **DF(단편화 수행 금지)** 와 **MF(단편화 패킷이 뒤에 더 있음)** 표시 역할을 함.
  3. **단편화 오프셋**: 단편화된 패킷이 초기 데이터에서 얼마나 떨어져 있는지를 나타내며, 수신지에서 순서대로 재조합할 때 사용됨.

### 신뢰할 수 없는 통신과 비연결형 통신
#### 1. 신뢰할 수 없는 프로토콜
- 패킷이 수신지까지 제대로 전송되었다고 보장하지 않는 프로토콜을 의미함.
- 패킷이 유실되거나 목적지에 순서대로 전송되지 않더라도 이에 대한 별도의 조치를 취하지 않음.
- 이러한 신뢰성이 낮고 보장이 없는 전송 특징을 **최선형 전달**이라고 부름.

#### 2. 비연결형 프로토콜
- 패킷을 주고받기 전에 사전 연결 과정을 거치지 않는 프로토콜을 의미함.
- 상대 호스트의 수신 가능 여부를 고려하지 않고 목적지를 향해 바로 패킷을 전송함.
- 반면 전송 계층의 대표적 프로토콜인 TCP는 송수신지 간 사전 연결을 수립하여 수신 준비가 되었는지 확인한 뒤 통신을 진행함.

> **IP 단편화 피하기 - 경로 MTU 발견**
>  - 잦은 IP 단편화는 트래픽 증가 및 성능 저하를 초래함.
>  - 수신지까지 가는 경로에 존재하고 처리 가능한 최소 MTU(=경로 MTU) 크기만큼만 송수신하여, 단편화 자체를 회피하는 기술임.

## IP 주소의 구조
- IPv4 기준 10진수 4개(32비트)로 구성되고, 크게 네트워크 주소와 호스트 주소로 이루어져 있음.
  - **네트워크 주소**: 호스트가 속한 네트워크를 식별함.
  - **호스트 주소**: 해당 네트워크 내에서 특정 호스트를 식별함.
- 네트워크 주소를 표현하는 크기와 호스트를 표현하는 크기가 유동적임.

### 클래스풀 주소 체계
- 네트워크 크기에 따라 A, B, C, D, E 클래스로 유형별 IP 주소를 분류함. (D, E는 각 멀티캐스트 및 특수 목적용)

| 클래스 | 첫 옥텟 비트 패턴 | 네트워크 주소 크기 | 호스트 주소 크기 | IP 주소 범위 |
| :--- | :--- | :--- | :--- | :--- |
| **A 클래스** | `0...` | 8비트 (1옥텟) | 24비트 (3옥텟) | `0.0.0.0 ~ 127.255.255.255` |
| **B 클래스** | `10...` | 16비트 (2옥텟) | 16비트 (2옥텟) | `128.0.0.0 ~ 191.255.255.255` |
| **C 클래스** | `110...` | 24비트 (3옥텟) | 8비트 (1옥텟) | `192.0.0.0 ~ 223.255.255.255` |

> - **예약된 예외 주소**
>   - **네트워크 주소**: 호스트 주소 비트가 모두 `0`인 주소로, 네트워크 자체를 지칭함.
>   - **브로드캐스트 주소**: 호스트 주소 비트가 모두 `1`인 주소로, 해당 네트워크의 전 호스트 대상으로 전송함.
>   - **루프백 주소**: `127.0.0.1`, 자기 자신(localhost)을 가리키는 검증용 주소임.

### 클래스리스 주소 체계와 서브넷 마스크
- 클래스풀 주소 체계는 IP 주소가 낭비될 수 있다는 한계가 있음.
- **클래스리스 주소 체계**는 클래스에 구애받지 않고 유동적인 크기로 네트워크 영역을 나누어 IP 낭비를 방지하는 주소 체계임.
- **서브넷 마스크**: IP 주소에서 어디까지가 네트워크 주소이고 어디서부터가 호스트 주소인지를 구분하기 위한 비트열임.
  - 네트워크 영역은 `1`, 호스트 영역은 `0`으로 채움.(ex. C클래스 기본 서브넷 마스크는 `255.255.255.0`)
  - IP 주소와 서브넷 마스크를 **비트 AND 연산**하면 실제 속한 네트워크 주소를 도출해냄.
- **CIDR 표기법 (Classless Inter-Domain Routing)**: IP 주소 뒤에 슬래시(`/`)와 서브넷 마스크의 1의 개수를 덧붙여 표기하는 방식임.
  - 예: `192.168.20.3/30` (네트워크 비트가 30비트임을 뜻하며, 서브넷 마스크 `255.255.255.252`와 동일)


## 공인 IP 주소와 사설 IP 주소
- **공인 IP 주소**: 전 세계에서 고유하며, 인터넷 통신을 위해 ISP나 IP 할당 기관으로부터 부여받는 공식 주소임.
- **사설 IP 주소**: 사설 네트워크(LAN) 내부에서 호스트들을 식별하기 위해 라우터/공유기가 부여하는 주소임. 사설 IP는 서로 다른 사설 네트워크 간에 중복 사용이 가능함.
- **사설 IP 주소로 예약된 공간**:
  - `10.0.0.0 ~ 10.255.255.255` (`10.0.0.0/8`)
  - `172.16.0.0 ~ 172.31.255.255` (`172.16.0.0/12`)
  - `192.168.0.0 ~ 192.168.255.255` (`192.168.0.0/16`)
- **주소 확인 명령어**: 윈도우: `ipconfig/all`,  맥OS / 리눅스: `ifconfig`

## IP 주소의 할당

### 정적 할당
- 사용자가 운영체제 설정이나 명령어를 통해 수동으로 직접 정적 IP 주소를 지정하여 부여하는 방식임.
- **설정 항목**: `IP 주소`, `서브넷 마스크`, `게이트웨이 주소`, `DNS 주소`가 필요함.
  - **기본 게이트웨이**: 호스트가 속한 사설 네트워크 외부로 나가는 첫 관문(라우터/공유기)의 IP 주소임.
  - **DNS 서버**: 도메인 네임(`google.com`)을 IP 주소로 변환하기 위해 질의하는 서버임.

### 동적 할당: DHCP
- 프로토콜을 통해 사용 가능한 IP 주소 목록을 관리하는 **DHCP 서버(공유기/라우터가 수행)** 가 IP 주소를 자동으로 부여해 주는 방식임.
- **특징**:
  - **임대 기간 (Lease Time)**: 동적 IP는 부여받아 사용 가능한 제한 시간이 정해져 있음.
  - **임대 갱신 (Lease Renewal)**: 사용 기간 만료 전에 임대 기간 연장을 시도하며, 일반적으로 두 번의 임대 갱신 실패 시 사용 중이던 IP는 반납되어 서버로 되돌아감.
  - 할당받을 때마다 다른 동적 IP 주소를 할당받을 수 있음.


## IP 전송 특징의 보완: ICMP
- **ICMP(Internet Control Message Protocol)**: 신뢰성이 없고 비연결형인 IP 특징을 보완하기 위한 프로토콜임.
  1. **오류 보고 메시지**: 패킷 전송 실패 원인을 송신지 호스트에 알려줌.
  - `Destination network/host/port unreachable`: 네트워크/호스트/포트 도달 불가
  - `Fragmentation required, and DF flag set`: 단편화가 필요하지만 DF가 1로 지정되어 전송 불가
  - `TTL expired in transit`: TTL 만료
  2. **네트워크 진단 정보 제공 메시지**:
  - `Echo request` / `Echo reply`: Echo 요청 및 응답 - 네트워크 통신 가능 여부를 점검함.
- **ICMP 관련 명령어**:
  - `ping`: 패킷을 송신하여 상대 호스트와의 통신 및 상태를 점검함 (`Echo request`/`Echo reply` 기반).
  - `traceroute`(윈도우: `tracert`): 목적지까지 거치는 경로를 확인하는 명령어임.
- **TTL(Time To Live) 필드**: IP 헤더에 명시되며 패킷이 라우터를 하나 `1홉`을 거칠 때마다 1씩 감소함. `0`이 되면 패킷이 폐기되어 무한 루프를 방지함.


## IP 주소와 MAC 주소의 대응: ARP
- **ARP**: 동일 네트워크 LAN 상에서 IP 패킷을 올바르게 전송하기 위해, 상대방의 **IP 주소를 바탕으로 물리적 주소인 MAC 주소를 알아내는 프로토콜**임.
  1. **ARP 요청**: 수신지의 MAC 주소를 모를 때, 대응되는 IP 주소를 명시하여 네트워크 내 모든 호스트에 **브로드캐스트**로 전송함.
  2. **ARP 응답**: 자신에 해당하는 IP 주소를 가진 호스트만 자신의 MAC 주소를 담아 요청 호스트에 답변함. (다른 호스트들은 요청을 무시함)
  3. **ARP 테이블**: 매번 브로드캐스트를 날리는 낭비를 줄이기 위해 알아낸 `<IP 주소, MAC 주소>` 대응 항목을 표 형태로 메모리에 임시 저장하여 유지함. 일정 시간이 지나면 삭제되며 수동으로도 삭제 가능함.
- **ARP 테이블 확인 명령어**: `arp -a`
