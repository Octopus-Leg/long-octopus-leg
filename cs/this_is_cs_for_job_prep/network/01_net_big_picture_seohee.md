# 5.1 네트워크의 큰 그림

## 네트워크의 기본 구조
- **네트워크**: 네트워크 기기인 `노드`와 유무선 통신 매체인 `간선`으로 이루어진 그래프 형태를 띰.
- **네트워크 토폴로지**: 네트워크 상에서 노드와 노드 사이의 연결 구조를 의미하며, 망형, 트리형, 링형 등의 유형으로 나눌 수 있음.
- **호스트**: 네트워크의 가장자리에 위치하면서 네트워크를 통해 주고받는 정보를 최초로 송신하고 최종 수신하는 노드를 말함. (노트북과 구글의 서버 컴퓨터가 호스트임.)
  - **클라이언트**: 노트북처럼 서비스를 요청하는 호스트임.
  - **서버**: 구글의 서버 컴퓨터처럼 요청에 대한 응답을 보내는 호스트임.
- **중간 노드**: 네트워크 그래프의 중간에 위치하여, 가장자리의 호스트들이 주고받는 정보(패킷)를 원하는 목적지까지 안정적으로 전송하는 역할을 수행함.

### LAN과 WAN
- **LAN(Local Area Network)**: 가정이나 기업처럼 비교적 가까운 거리를 연결하는 한정된 공간에서의 네트워크를 뜻함.
- **WAN(Wide Area Network)**: LAN과 LAN 간의 원거리 통신을 의미하며, 일반적으로 ISP(인터넷 서비스 제공업체)가 구축하고 관리함.
  - 국내 대표 ISP 업체: KT, LG유플러스, SK브로드밴드 등

### 패킷 교환 네트워크
- **패킷**: 네트워크를 통해 송수신되는 데이터의 기본 단위임. 대용량 파일 전송 시 데이터를 여러 개의 작은 단위로 쪼개어 전송함.
- **패킷의 구성 요소**:
  - **페이로드**: 패킷에서 실제로 송수신하고자 하는 실질적인 데이터 본체임. (택배의 내용물 역할)
  - **헤더와 트레일러**: 패킷의 앞뒤에 추가되는 부가 정보로, 송수신지 주소나 오류 제어 정보 등이 담김. (택배의 송장 역할)

### 주소의 개념과 전송 방식
- **주소**: 패킷의 헤더에 명시되는 정보이며, 네트워크에서 식별자로 사용되는 대표적인 주소로는 `IP 주소`와 `MAC 주소`가 있음.

#### 전송 방식 (표로 정리해줘.)
| 전송 방식 | 정의 및 특징                                                                                                                  |
| :--- |:-------------------------------------------------------------------------------------------------------------------------|
| **유니캐스트** | 송신지와 수신지가 **일대일**로 명확하게 메시지를 주고받는 전송 방식임.                                                                                |
| **브로드캐스트** | **네트워크상의 모든 호스트**에게 메시지를 동시에 전송하는 방식임.<br>- **브로드캐스트 도메인**: 브로드캐스트 패킷이 도달하는 범위를 뜻하며, 같은 도메인에 속해 있다면 동일한 LAN에 속한 것으로 간주함. |
| **멀티캐스트** | 네트워크 내에서 지정된 **특정 그룹에 속한 호스트들**에게만 메시지를 전송하는 방식임.                                                                        |
| **애니캐스트** | 동일한 그룹에 속한 호스트 중 **송신지와 가장 가까운 호스트**에게만 패킷을 전송하는 방식임.                                                                    |


## 두 호스트가 패킷을 주고받는 과정
### 프로토콜
- **프로토콜**: 네트워크에서 통신을 주고받는 노드 간에 **합의된 규칙이나 방법**을 의미함.
- 패킷을 주고받는 호스트와 중간 네트워크 장비들이 정보를 올바르게 이해하려면 반드시 동일한 프로토콜을 사용하여 통신해야 함.
- **주요 프로토콜**:
  - **IP**: 네트워크 간의 주소를 지정하고 경로를 설정함.
  - **ARP**: IP 주소를 물리적인 MAC 주소로 대응시킴.
  - **HTTPS**: HTTP에 보안을 추가하여 안전하게 통신함.
  - **TCP**: UDP에 비해 데이터 전송의 신뢰성이 매우 높음.

### 네트워크 참조 모델
- **네트워크 참조 모델**: 통신이 이루어지는 단계를 독립적인 계층으로 나누어 표현한 구조적 모델임.

#### OSI 모델(OSI 7계층)

| 계층            | 특징                                                                                        |
|:--------------|:------------------------------------------------------------------------------------------|
| **응용 계층**     | 사용자에게 여러 네트워크 서비스를 직접 제공하는 최상위 계층으로, `HTTP`, `HTTPS`, `DNS` 등이 속함.                        |
| **표현 계층**     | 데이터의 인코딩/디코딩, 압축/해제, 암호화/복호화 같은 작업을 수행함.                                                  |
| **세션 계층**     | 응용 프로그램 간의 연결 상태를 의미하는 '세션'을 관리하며, 연결의 생성, 유지, 종료를 제어함.                                   |
| **전송 계층**     | 신뢰성 있는 데이터 전송을 보장하는 계층임. `포트(Port)` 번호를 통해 특정 응용 프로그램과의 연결 다리 역할을 수행하며, `TCP`와 `UDP`가 있음. |
| **네트워크 계층**   | 서로 다른 네트워크 간의 최적의 통신 경로를 설정하는 계층으로, `IP` 프로토콜이 사용됨.                                       |
| **데이터 링크 계층** | 동일 LAN에 속한 호스트끼리 올바르게 정보를 주고받기 위한 계층임. `MAC 주소`를 사용하며 물리 계층의 오류를 탐지함.                     |
| **물리 계층**     | 최하위 계층으로, 데이터를 0과 1로 이루어진 **비트 신호**로 변환하여 유무선 매체로 전송함.                                    |


#### TCP/IP 모델(TCP/IP 4계층)
- 구현과 프로토콜에 중점을 둔 네트워크 참조 모델임.

| 계층              | 특징                                                             |
|:----------------|:---------------------------------------------------------------|
| **응용 계층**       | OSI 모델의 세션 계층, 표현 계층, 응용 계층을 하나로 합친 것과 유사함.                    |
| **전송 계층**       | OSI 모델의 전송 계층과 유사하며, 데이터의 신뢰성을 관리함.                            |
| **인터넷 계층**      | OSI 모델의 네트워크 계층과 유사하며, IP 패킷의 경로를 제어함.                         |
| **네트워크 액세스 계층** | 링크 계층 혹은 네트워크 인터페이스 계층이라고도 불림. OSI 모델의 데이터 링크 계층 및 물리 계층과 유사함. |

> 책에서는 TCP/IP 모델에 물리 계층을 추가한 모델로 네트워크를 설명함.


### 캡슐화와 역캡슐화
- **캡슐화**: 송신 호스트에서 상위 계층의 데이터가 하위 계층으로 내려가며 **각 계층의 헤더 및 트레일러를 추가**해 나가는 과정임.
- **역캡슐화**: 수신 호스트에서 하위 계층의 패킷이 상위 계층으로 올라가며 붙어 있던 **헤더 및 트레일러를 확인한 뒤 제거**하는 과정임.

#### 계층별 패킷 데이터 단위
| 계층        | 데이터 단위 명칭                   |
|-----------|-----------------------------|
| 그 이상의 계층  | 데이터 또는 메시지                  |
| 전송 계층     | TCP - 세그먼트 <br> UDP - 데이터그램 |
| 네트워크 계층   | 패킷 또는 데이터그램                 |
| 데이터 링크 계층 | 프레임                         |
| 물리 계층     | 심볼 또는 비트                    |


## 네트워크 지도 그리기
### 1. 물리 계층과 데이터 링크 계층
- 이더넷
- 유무선 통신 매체
- 이더넷 프레임
- 다양한 네트워크 장비(NIC/허브/스위치)

### 2. 네트워크 계층
- IP의 목적과 특징
- IP 주소
  - IP 주소의 구조(클래스풀 주소 체계/클래스리스 주소 체계와 서브넷 마스크)
  - IP 주소의 종류: 공인 IP 주소와 사설 IP 주소
  - IP의 할당(정적 할당/동적 할당: DHCP)
- ICMP
- ARP

### 3. 전송 계층
- TCP
  - TCP의 목적과 특징
  - TCP의 연결 수립과 종료
  - TCP의 오류, 흐름, 혼잡 제어
  - TCP의 상태 관리
- UDP
  - UDP의 목적과 특징

### 4. 응용 계층
- DNS와 URI/URL
- HTTP
  - HTTP의 목적과 특징
  - HTTP 메시지 구조(메서드/상태 코드/주요 헤더)
  - HTTP 기반 기술(쿠키/캐시/콘텐츠 협상)
- HTTPS
  - SSL/TLS

### 5. 프록시와 안정적인 트래픽
- 중간 서버(포워드 프록시/리버스 프록시)
- 안정성(가용성과 고가용성/로드 밸런싱/스케일링: 스케일 업과 스케일 아웃)
