# 5.4 전송 계층 - TCP와 UDP

## TCP와 UDP의 목적과 특징

### 포트를 통한 프로세스 식별
- **필요성**: IP 주소와 MAC 주소는 패킷을 주고받는 호스트 장치 자체를 특정함. 하지만 패킷의 최종 송수신 대상은 호스트에서 실행 중인 **프로세스**임.
- **포트**: 네트워크 패킷을 주고받는 프로세스를 식별하기 위해 부여되는 번호임.
- **식별 방법**: `IP 주소 : 포트 번호` 형식으로 특정 호스트의 특정 프로세스를 식별함.
- **포트 번호의 범위 (16비트, 총 65,536개)**:
  1. **잘 알려진 포트(`0 ~ 1023`)**: 범용 프로토콜이 주로 사용하는 포트 번호임.
    - `20, 21`: FTP / `22`: SSH / `23`: TELNET / `53`: DNS / `67, 68`: DHCP / `80`: HTTP / `443`: HTTPS
  2. **등록된 포트(`1024 ~ 49151`)**: 특정 애플리케이션 프로토콜이 할당받아 사용하는 포트 번호임.
    - `1194`: OpenVPN / `1433`: MS SQL / `3306`: MySQL / `6379`: Redis / `8080`: HTTP 대체
  3. **동적 포트(`49152 ~ 65535`)**: 사설 포트 또는 임시 포트로 불리며, 클라이언트 프로그램이 동적으로 임의 할당받아 사용함.

> **NAT와 NAPT**
> - **NAT**: 사설 IP 주소와 공인 IP 주소를 1:1로 변환하는 기술임.
> - **NAPT**: IP 주소 변환 과정에서 **포트 번호까지 함께 고려**하여 변환 및 기록하는 기술임. 하나의 공인 IP 주소를 여러 사설 IP 주소가 공유할 수 있어 공인 IP 고갈 문제를 개선함.

### (비)신뢰성과 (비)연결형 보장
- **TCP**: **신뢰할 수 있는 연결형 프로토콜**임.
  - 패킷 송수신 전 연결 수립 과정을 거치며, 연결 수립 후 패킷을 주고받을 때 상태 관리, 흐름 제어, 오류 제어, 혼잡 제어 기능을 제공함.
  - 패킷 유실 없는 신뢰할 수 있는 통신이 필요할 때 적합함.
- **UDP**: **신뢰할 수 없는 비연결형 프로토콜**임.
  - 연결 수립이나 종료 단계를 거치지 않으며, 상태 관리, 흐름 제어, 오류 제어, 혼잡 제어 기능을 제공하지 않음.
  - 오버헤드가 적어 비교적 빠른 송수신이 필요한 경우에 적합함.



## TCP의 연결부터 종료까지

### TCP의 연결 수립
- **쓰리 웨이 핸드셰이크**: 송수신 호스트 간 세 단계를 거쳐 논리적 연결을 수립함.
- **주요 제어 비트**:
  - `SYN`: 연결을 수립하기 위한 비트임.
  - `ACK`: 세그먼트 수신 승인을 나타내는 비트임.
  - `FIN`: 연결을 종료하기 위한 비트임.
- **단계별 동작 과정**:
  1. **1단계**: 클라이언트(액티브 오픈)가 서버(패시브 오픈)에 `SYN` 비트가 1로 설정된 세그먼트와 초기 순서 번호를 보냄.
  2. **2단계**: 서버가 승인 의미로 `ACK` 비트와 `SYN` 비트를 1로 설정하고, 요청 세그먼트에 대한 확인 응답 번호(받은 순서 번호 + 1)를 함께 보냄.
  3. **3단계**: 클라이언트가 `ACK` 비트가 1로 설정된 세그먼트와 응답 번호를 전송하여 최종 연결을 수립함.

### TCP의 오류·흐름·혼잡 제어

#### 1. 재전송을 통한 오류 제어
- 손실되거나 잘못 전송된 세그먼트가 있을 때 이를 재전송하여 오류를 바로잡는 기능임.
- **오류 인지 상황**
  1. **중복된 ACK 세그먼트 수신**: 전송한 세그먼트 일부가 손실되어 수신 측이 동일한 `ACK` 세그먼트를 반복하여 보낼 때 인지함.
  2. **타임아웃 발생**: 세그먼트 전송 시 재전송 타이머가 작동하며, 카운트다운이 끝날 때까지 `ACK` 세그먼트를 받지 못하면 타임아웃으로 판단해 해당 세그먼트를 재전송함.
- **파이프라이닝 전송**: 확인 응답을 받기 전이라도 연속해서 여러 세그먼트를 보내는 전송 방식으로 효율성을 높임.

#### 2. 흐름 제어
- 수신 호스트의 처리 속도를 고려하여 송신 호스트의 전송 속도를 맞추는 기능임.
- 수신 버퍼의 남은 공간 크기인 **수신 윈도우** 값을 헤더에 담아 송신 측에 알림. 송신 측은 수신 윈도우 크기를 초과하지 않는 범위 내에서 세그먼트를 전송함.

#### 3. 혼잡 제어
- 네트워크 내부의 트래픽 혼잡도를 송신 호스트가 스스로 판단하여 전송량을 조절하는 기능임.
- 송신 측은 중복 `ACK` 수신이나 타임아웃 발생 여부로 혼잡을 판단함. 네트워크에 혼잡이 없다고 판단되는 만큼 전송할 수 있는 세그먼트 양인 **혼잡 윈도우** 크기를 계산하여 조절함.
- **혼잡 제어 알고리즘(AIMD)**
  - 혼잡이 감지되지 않으면 혼잡 윈도우를 RTT마다 1씩 선형적으로 증가시킴.
  - 혼잡이 감지되면 혼잡 윈도우를 절반으로 떨어뜨림.

### TCP의 종료
- **포 웨이 핸드셰이크**: 송수신 호스트가 각자 한 번씩 `FIN`과 `ACK` 세그먼트를 주고받으며 총 4단계를 거쳐 연결을 종료함.
- **액티브 클로즈와 패시브 클로즈**:
  - 먼저 연결 종료 요청을 보낸 호스트의 동작을 **액티브 클로즈**라고 함.
  - 연결 종료 요청을 받아들이는 호스트의 동작을 **패시브 클로즈**라고 함.
- **단계별 동작 과정**:
  1. **1단계**: 액티브 클로즈 호스트가 `FIN` 세그먼트를 전송함.
  2. **2단계**: 패시브 클로즈 호스트가 응답으로 `ACK` 세그먼트를 전송함.
  3. **3단계**: 패시브 클로즈 호스트가 자신의 정리 작업을 마치고 `FIN` 세그먼트를 전송함.
  4. **4단계**: 액티브 클로즈 호스트가 응답으로 `ACK` 세그먼트를 전송함.
- **주의점**: 패시브 클로즈 호스트는 마지막 `ACK` 세그먼트를 수신하면 바로 종료(`CLOSED`) 상태가 됨. 반면 액티브 클로즈 호스트는 마지막 `ACK` 세그먼트가 유실될 경우를 대비해 바로 종료하지 않고 일정 시간을 기다리는 **`TIME-WAIT`** 상태를 거친 뒤 종료함.


## TCP의 상태 관리
- **스테이트풀 프로토콜**: TCP는 송수신 과정에서 상태를 유지하고 관리함. `netstat` 명령어 등을 통해 현재 상태 정보를 확인할 수 있음.

### 주요 TCP 상태 분류

#### 1. 연결이 수립되지 않았을 때
- **`CLOSED`**: 아무런 연결이 없는 상태임.
- **`LISTEN`**: 연결 대기 상태로, 패시브 오픈 호스트(서버)가 `SYN` 세그먼트를 기다리는 상태임.

#### 2. 연결 수립 과정 - `3-way handshake`
- **`SYN-SENT`**: 액티브 오픈 호스트가 `SYN` 세그먼트를 보낸 뒤 응답(`SYN+ACK`)을 기다리는 상태임.
- **`SYN-RECEIVED`**: 패시브 오픈 호스트가 `SYN+ACK` 세그먼트를 보낸 뒤 응답(`ACK`)을 기다리는 상태임.
- **`ESTABLISHED`**: 연결 수립이 완료되어 데이터를 송수신할 수 있는 상태임.

#### 3. 연결 종료 과정 - `4-way handshake`
- **`FIN-WAIT-1`**: 액티브 클로즈 호스트가 `FIN` 세그먼트로 연결 종료 요청을 보낸 상태임.
- **`CLOSE-WAIT`**: `FIN` 세그먼트를 받은 패시브 클로즈 호스트가 `ACK` 세그먼트를 보낸 후 대기하는 상태임.
- **`FIN-WAIT-2`**: 액티브 클로즈 호스트가 `ACK` 세그먼트를 받은 후, 상대의 `FIN` 세그먼트를 기다리는 상태임.
- **`LAST-ACK`**: 패시브 클로즈 호스트가 `FIN` 세그먼트를 보낸 뒤 마지막 `ACK`를 기다리는 상태임.
- **`TIME-WAIT`**: 액티브 클로즈 호스트가 마지막 `ACK` 세그먼트를 전송한 뒤, 재전송 가능성에 대비해 일정 시간을 대기하는 상태임.
- **`CLOSING`**: 양쪽 호스트가 동시에 `FIN` 세그먼트를 보내어 서로의 종료 응답을 기다릴 때 발생하는 특수 상태임.
