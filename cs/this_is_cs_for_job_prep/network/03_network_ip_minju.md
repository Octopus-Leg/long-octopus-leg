## 3. 네트워크 계층 - IP

### IP의 목적과 특징

**IP(Internet Protocol)** 의 본래 목적은 크게 **주소 지정(addressing)** 과 **단편화(fragmentation)** 2가지로 나뉨.

- **주소 지정**: 네트워크 간 통신 과정에서 호스트를 특정함.
- **단편화**: 데이터를 여러 IP 패킷으로 올바르게 쪼개어 보냄.
- IP는 **'신뢰할 수 없는 통신'** 과 **'비연결형 통신'** 이라는 특징도 가짐.

#### 주소 지정과 단편화

주소 지정은 IP 패킷 헤더의 **송신지 IP 주소**와 **수신지 IP 주소** 필드를 통해 이루어짐.

- 하나의 IP 주소는 총 4바이트(32비트)로 구성되고, 8비트씩 0~255 범위의 10진수 4개로 표기됨. 점(.)으로 구분된 하나의 10진수를 **옥텟(octet)** 이라고 함. (예: `192.168.0.1`)
- MAC 주소는 택배 배송 과정의 수신인/발신인, IP 주소는 수신 주소/발신 주소에 빗댈 수 있음. 패킷 송수신 과정에서는 MAC 주소보다 IP 주소가 우선적으로 활용됨.

**라우터(router)** : 서로 다른 네트워크에 속한 두 호스트가 통신할 때 IP 주소를 바탕으로 목적지까지 IP 패킷을 전달하는 네트워크 장비임.

- 전달받은 IP 패킷을 전달할 **최적의 경로를 결정**하고 해당 경로로 내보내는 과정을 **라우팅(routing)** 이라고 함.
- 공유기도 라우팅을 수행할 수 있으므로 라우터의 일종임.

> IPv4 주소는 총 32비트로, 이론적으로 할당 가능한 주소는 약 43억(2³²)개임. 고갈될 여지가 있어 등장한 것이 **IPv6**임.<br>
> IPv6 주소는 16바이트(128비트)로 표현되어 이론적으로 사실상 무한(2¹²⁸)에 가까움. 콜론(:)으로 구분된 8개 그룹의 16진수로 표기됨. (예: `2001:0230:abcd:ffff:0000:0000:ffff:1111`).

**MTU(Maximum Transmission Unit)** : 최대 전송 단위를 의미함. 전송하려는 IP 패킷(헤더+페이로드)의 크기가 MTU보다 크면 MTU 이하의 여러 패킷으로 쪼개 전송하고, 수신지에서 재조립함.

- 일반적인 MTU 크기는 1500바이트임. (=프레임에 실릴 수 있는 최대 데이터 크기)

IP 패킷 헤더에서 단편화와 관련된 필드는 3가지임.

| 필드 | 설명 |
|---|---|
| **식별자(identifier)** | 특정 패킷이 어떤 데이터에서 쪼개진 패킷인지 식별하기 위해 사용되는 필드. 같은 정보에서 쪼개진 패킷들은 같은 식별자를 공유함 |
| **플래그(flag)** | 3비트로 구성된 필드. 첫 비트는 항상 0(오늘날 미사용). **DF**는 'IP 단편화를 수행하지 말라(Don't Fragment)', **MF**는 '단편화된 패킷이 더 있다(More Fragment)' 표시 |
| **단편화 오프셋(fragment offset)** | 특정 패킷이 초기 데이터에서 얼마나 떨어져 있는지 명시된 필드. 재조합 시 올바른 순서를 나타내는 데 사용됨 |

#### 신뢰할 수 없는 통신과 비연결형 통신

- **신뢰할 수 없는 프로토콜(unreliable protocol)** : 패킷이 수신지까지 제대로 전송되었다고 보장하지 않음. 유실되거나 순서대로 전송되지 않아도 조치를 취하지 않음. **최선형 전달(best effort delivery)** 이라고도 부르지만, 어떠한 보장도 하지 않는 전송 특징임.
- **비연결형 프로토콜(connectionless protocol)** : 패킷을 주고받기 전에 사전 연결 과정을 거치지 않음. 상대 호스트의 수신 가능 여부를 고려하지 않고 그저 패킷을 전송함.

### IP 주소의 구조

하나의 IP 주소는 크게 **네트워크 주소**와 **호스트 주소**로 이루어짐.

| 구분 | 설명 |
|---|---|
| **네트워크 주소** | 네트워크 ID, 네트워크 식별자 등으로 불림. 호스트가 속한 네트워크를 특정함 |
| **호스트 주소** | 호스트 ID, **호스트 식별자(host identifier)** 등으로 불림. 네트워크에 속한 호스트를 특정함 |

- 하나의 IP 주소에서 네트워크 주소를 표현하는 크기와 호스트 주소를 표현하는 크기는 유동적일 수 있음.
- 네트워크 주소 공간을 작게 호스트 주소 공간을 크게 하면 네트워크당 많은 호스트에 IP 주소를 할당할 수 있고, 반대의 경우 네트워크당 적은 호스트에 할당할 수 있음.

#### 클래스풀 주소 체계

**클래스(class)** 는 네트워크 크기에 따라 유형별로 IP 주소를 분류하는 기준임. 이를 바탕으로 IP 주소를 관리하는 체계를 **클래스풀 주소 체계(classful addressing)** 라고 함.

- 클래스는 A, B, C, D, E 총 5개이며, D와 E는 멀티캐스트/특수 목적용으로 예약됨. 실질적으로 IP 주소를 분류하는 데 사용되는 클래스는 A, B, C임.
- 첫 옥텟의 주소만 보고도 어떤 클래스인지 알 수 있음.

| 클래스 | 네트워크 주소 | 호스트 주소 | IP 주소 표현 가능 범위 |
|---|---|---|---|
| **A 클래스** | 비트 `0`으로 시작, 1옥텟 | 3옥텟 | 0.0.0.0 ~ 127.255.255.255 |
| **B 클래스** | 비트 `10`으로 시작, 2옥텟 | 2옥텟 | 128.0.0.0 ~ 191.255.255.255 |
| **C 클래스** | 비트 `110`으로 시작, 3옥텟 | 1옥텟 | 192.0.0.0 ~ 223.255.255.255 |

#### 클래스리스 주소 체계와 서브넷 마스크

클래스풀 주소 체계는 클래스별 네트워크 크기가 고정되어 IP 주소가 낭비될 수 있는 한계가 있음. 이를 해결하기 위해 등장한 것이 **클래스리스 주소 체계(classless addressing)** 로, 클래스를 이용하지 않고 네트워크와 호스트를 구분하는 방식임.

- **서브넷 마스크(subnet mask)** : IP 주소상에서 네트워크 주소를 1로, 호스트 주소를 0으로 표기한 비트열
- **서브네트워크(subnetwork, 서브넷)** : IP 주소에서 네트워크 주소로 구분할 수 있는 네트워크의 부분집합
- **서브네팅(subnetting)** : 서브넷 마스크로 원하는 크기만큼 클래스를 더 잘게 쪼개어 사용하는 것

클래스별 기본 서브넷 마스크

- **A 클래스**: `255.0.0.0` (11111111.00000000.00000000.00000000)
- **B 클래스**: `255.255.0.0` (11111111.11111111.00000000.00000000)
- **C 클래스**: `255.255.255.0` (11111111.11111111.11111111.00000000)

서브넷 마스크와 IP 주소 간에 **비트 AND 연산**을 수행하면 네트워크 주소를 알아낼 수 있음.

```
IP 주소          11000000.10101000.11001000.01100110  (192.168.200.102)
서브넷 마스크     11111111.11111111.11111111.00000000  (255.255.255.0)
              ─────────────────────────────────────────
비트 AND 연산    11000000.10101000.11001000.00000000 = 192.168.200.0
```

> 'IP 주소/서브넷 마스크상의 1의 개수' 형식으로 표기하는 방법을 **CIDR 표기법(Classless Inter-Domain Routing notation)** 이라고 함.<br>
> 예를 들어 `192.168.20.3/30`에서 `/30`은 서브넷 마스크 상에 1이 총 30개(11111111.11111111.11111111.11111100)라는 의미이므로, `/30`은 `255.255.255.252`와 같은 표기임.

### 공인 IP 주소와 사설 IP 주소

호스트의 IP 주소는 네트워크 설정, 명령어(윈도우 `ipconfig/all`, 맥OS·리눅스 `ifconfig`), 온라인 검색 등으로 확인할 수 있음. 고유한 IP 주소도 있고 고유하지 않은 IP 주소도 있으며, 두 종류가 함께 사용되는 경우가 많음.

| 구분 | 설명 |
|---|---|
| **공인 IP 주소(public IP address)** | 전 세계에서 고유한 IP 주소. 인터넷을 비롯한 네트워크 간 통신에 사용됨. ISP나 공인 IP 주소 할당 기관을 통해 할당받음 |
| **사설 IP 주소(private IP address)** | 사설 네트워크(외부에 공개되지 않은 네트워크)에서 사용하는 IP 주소. 일반적으로 라우터(공유기)를 통해 할당됨 |

**사설 IP 주소로 사용하도록 예약된 IP 주소 공간**

- `10.0.0.0/8` (10.0.0.0 ~ 10.255.255.255)
- `172.16.0.0/12` (172.16.0.0 ~ 172.31.255.255)
- `192.168.0.0/16` (192.168.0.0 ~ 192.168.255.255)
- 사설 IP 주소는 해당 사설 네트워크상에서만 유효하므로 다른 네트워크상의 사설 IP 주소와 중복될 수 있음.

### IP 주소의 할당

호스트에 IP 주소를 할당하는 방법은 크게 **정적 할당**과 **동적 할당** 2가지가 있음.

#### 정적 할당

**정적 할당**은 직접 수작업으로 IP 주소를 부여하는 방식으로, 이렇게 할당된 IP 주소를 **정적 IP 주소**라고 함.

- 정적 IP 주소를 부여하기 위해 필요한 값: 부여할 IP 주소, 서브넷 마스크, 게이트웨이(라우터) 주소, DNS 주소
- **게이트웨이**: 서로 다른 네트워크를 연결하는 하드웨어적/소프트웨어적 수단. **기본 게이트웨이**는 호스트가 속한 네트워크 외부로 나가기 위한 첫 경로로, 라우터(공유기)의 주소인 경우가 많음.
- **DNS 주소**: 호스트가 도메인 네임으로 IP 주소를 알아내기 위해 질의하는 서버(네임 서버, DNS 서버)의 주소. 공개된 대표적 네임 서버로 `8.8.8.8`, `1.1.1.1` 등이 있음.

#### 동적 할당: DHCP

**동적 할당**은 프로토콜을 통해 자동으로 IP 주소를 부여하는 방식으로, 이렇게 할당된 IP 주소를 **동적 IP 주소**라고 함. 가장 흔히 사용되는 프로토콜이 **DHCP(Dynamic Host Configuration Protocol)** 임.

- IP 주소를 동적으로 할당받으려는 호스트는 DHCP 서버와 메시지를 주고받으며 IP 주소를 할당받음. 일반적으로 라우터(공유기)가 DHCP 서버 역할을 함.
- 사용 기간이 끝난 IP 주소는 DHCP 서버로 반납됨. 임대 기간이 끝나기 전에 **임대 갱신(lease renewal)** 으로 연장할 수 있으며, 기본적으로 자동으로 두 차례 수행됨. 두 번의 갱신이 모두 실패하면 IP 주소는 반납됨.

**동적 IP 주소 기억해야 할 점**

- 사용 가능한 기간(임대 기간)이 정해져 있음.
- 할당받을 때마다 다른 주소를 받을 수 있음.

### IP 전송 특징의 보완: ICMP

IP는 신뢰할 수 없는 비연결형 프로토콜이며, 이는 주로 성능 때문임(신뢰성·연결형 송수신 처리는 시간, 대역폭, 부하가 필요해 '빠른' 송수신과 배치됨). 이러한 특징을 보완하는 방법은 2가지임.

1. 신뢰할 수 있는 연결형 통신을 지원하는 상위 계층 프로토콜(TCP) 이용하는 방법
2. 네트워크 계층 프로토콜인 **ICMP**를 이용하는 방법

**ICMP(Internet Control Message Protocol)** 는 IP 패킷의 전송 과정에 대한 피드백 메시지(ICMP 메시지)를 얻기 위해 사용하는 프로토콜임.

> 유의할 점은 ICMP가 IP의 신뢰성을 완전히 보장하지는 않는다는 점임. 완전히 보장하려면 전송 계층 프로토콜이 필요함.

ICMP 메시지는 크게 **① 전송 과정에서 발생한 오류 보고**와 **② 네트워크에 대한 진단 정보(네트워크 상의 정보 제공)** 로 나뉨.

| 유형 | 메시지 |
|---|---|
| **① 오류 보고** | 네트워크 도달 불가, 호스트 도달 불가, 프로토콜 도달 불가, 포트 도달 불가, 단편화가 필요하지만 DF가 1로 설정되어 단편화할 수 없음, TTL 만료 |
| **② 네트워크 상의 정보 제공** | Echo 요청(Echo request), Echo 응답(Echo reply) |

- **TTL(Time To Live)** : IP 헤더에 있는 패킷의 수명. 패킷이 하나의 라우터를 거칠 때마다 1씩 감소하며, 0이 되면 패킷이 폐기되고 송신 호스트에게 [시간 초과(time exceeded)] ICMP 메시지가 전송됨.
- 패킷이 호스트/라우터에 한 번 전달되는 것을 **홉(hop)** 이라고 함.
- ICMP 기반 대표 명령어: 네트워크 상의 경로를 확인하는 `traceroute`(윈도우 `tracert`), 네트워크 상태를 점검하기 위해 패킷을 송신하는 `ping`

### IP 주소와 MAC 주소의 대응: ARP

상대 호스트의 IP 주소는 알지만 MAC 주소는 모르는 상황에서 사용하는 프로토콜이 **ARP(Address Resolution Protocol)** 임. 동일 네트워크 내에 있는 송수신 대상의 IP 주소를 통해 MAC 주소를 알아냄.

**ARP의 동작 과정 (IP 주소 → MAC 주소)**

1. **ARP 요청 메시지**: 브로드캐스트 메시지. 알고 싶은 MAC 주소에 대응되는 IP 주소가 포함됨. ('이 IP 주소를 가진 호스트의 MAC 주소가 무엇인가요?'라고 소리치는 것과 같음.)
2. 네트워크 내 모든 호스트가 수신하되 자신과 무관한 IP 주소면 무시하고, 자신의 IP 주소면 **ARP 응답 메시지**를 전송함.
3. **ARP 응답 메시지**: 응답 호스트의 MAC 주소가 포함됨. 이를 통해 IP 주소로 MAC 주소를 알아냄.

- 호스트는 알게 된 <IP 주소, MAC 주소> 쌍을 **ARP 테이블(ARP table)** 로 유지함. 항목은 일정 시간이 지나면 삭제되며, 임의로 삭제할 수도 있음.
- 윈도우, 맥OS, 리눅스 터미널에서 명령어 `arp -a`로 확인할 수 있음.
