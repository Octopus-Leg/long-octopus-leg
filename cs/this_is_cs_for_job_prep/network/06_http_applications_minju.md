## 6. 응용 계층 - HTTP의 응용

### 쿠키

HTTP는 스테이트리스 프로토콜이라 모든 요청을 독립된 메시지로 간주함. 그런데 '3일간 보지 않기' 같은 기능은 클라이언트 상태를 알아야 구현 가능함. 이를 위해 **HTTP 쿠키(쿠키)** 를 활용함.

**쿠키**는 HTTP의 스테이트리스한 특성을 보완하기 위한 수단으로, 서버에서 생성되어 클라이언트 측에 저장되는 **<이름, 값> 쌍** 형태의 데이터임.

- 서버는 응답 메시지의 **Set-Cookie 헤더**로 쿠키를 전송하고, 클라이언트는 요청 시 **Cookie 헤더**로 쿠키를 건넴.
- 특정 서버로부터 쿠키를 전달받으면, 이후 해당 서버 요청에는 자동으로 쿠키가 포함됨.

```
응답 메시지
Set-Cookie: name=minchul
Set-Cookie: phone=100-100
 
요청 메시지
Cookie: name=minchul; phone=100-100; message=Hello
```

**쿠키의 대표적인 속성**

| 속성 | 설명 |
|---|---|
| **Domain, Path** | 쿠키를 전송할 도메인과 경로를 제한 |
| **Expires** | 쿠키 만료 시점 `[요일, DD-MM-YY HH:MM:SS GMT]` |
| **Max-Age** | 초 단위 유효기간 |
| **Secure** | HTTPS를 통해서만 쿠키를 송수신하도록 함 |
| **HttpOnly** | 자바스크립트를 통한 접근을 제한, 오직 HTTP 송수신으로만 접근 |

> **웹 스토리지: 로컬 스토리지와 세션 스토리지**: 웹 스토리지(web storage)는 웹 브라우저 내의 저장 공간으로, 쿠키보다 큰 데이터를 저장할 수 있음. 쿠키와 달리 서버로 자동 전송되지 않음. **로컬 스토리지(local storage)** 는 삭제 전까지 영구 저장, **세션 스토리지(session storage)** 는 세션이 유지되는 동안(브라우저가 열려 있는 동안)만 유지됨.

### 캐시

**HTTP 캐시(웹 캐시, 캐시)** 는 응답받은 자원의 사본을 임시 저장하여 불필요한 대역폭 낭비와 응답 지연을 방지하는 기술임.

- 클라이언트(주로 웹 브라우저)에 저장되면 **개인 전용 캐시(private cache)**, 중간 서버에 저장되면 **공용 캐시(public cache)** 라고 함.
- 유효기간 부여: 응답 메시지의 **Expires 헤더**(만료 날짜)와 **Cache-Control 헤더의 max-age 값**(초 단위 사용 가능 시간) 사용

캐시에 유효기간이 부여되는 이유는 원본 데이터가 변경되어 사본과의 일관성이 깨질 수 있기 때문임. 사본이 원본과 얼마나 유사한지는 **캐시 신선도**로 표현함.

- 유효기간이 만료되었더라도 원본이 변하지 않았으면 재응답받을 필요 없이 유효기간을 연장하면 됨,
- 클라이언트는 유효기간 만료 시 원본 변경 여부를 서버에 질의함. '날짜 기반' 또는 '엔티티 태그 기반'으로 물을 수 있음,

**날짜 기반 - If-Modified-Since 헤더**: 명시된 시점 이후로 원본에 변경이 있었다면 그때만 변경된 자원으로 응답하도록 요청함. 서버 응답은 3가지 경우로 나뉨.

| 상황 | 응답 |
|---|---|
| 자원이 변경된 경우 | 200(OK)과 새로운 자원 |
| 자원이 변경되지 않은 경우 | 본문 없이 304(Not Modified), Last-Modified 헤더로 마지막 변경 시점 안내 |
| 자원이 삭제된 경우 | 404(Not Found) |

**엔티티 태그 기반 - If-None-Match 헤더**: **엔티티 태그(ETag)** 는 '자원의 버전'을 식별하기 위한 정보임. 자원이 변경되면 ETag 값도 변경됨. If-None-Match에 명시된 ETag와 일치하는 ETag가 없으면(변경되었으면) 그때만 변경된 자원으로 응답함. 서버 응답은 If-Modified-Since와 동일하게 3가지 경우로 나뉨.

### 콘텐츠 협상

서버와 클라이언트가 HTTP 메시지로 주고받는 것은 엄밀히 자원의 **표현(representation)** 임. 표현이란 '송수신 가능한 자원의 형태'를 의미함.

- 같은 URI(URL)에 대해서도 여러 표현이 있을 수 있음 (예: 한국어 표현, 영어 표현).
- GET 메서드의 정확한 목적은 '자원 획득'이라기보다 '자원의 특정 표현 조회'에 가까움.
같은 자원에 대한 여러 표현 중 클라이언트가 가장 적합한 표현을 요청하는 기술을 **콘텐츠 협상(content negotiation)** 이라고 함.

**대표적인 콘텐츠 협상 헤더**

| 헤더 | 설명 |
|---|---|
| **Accept** | 선호하는 미디어 타입 |
| **Accept-Language** | 선호하는 언어 |
| **Accept-Encoding** | 선호하는 인코딩 방식 |

- 우선순위는 **q값(Quality Values)** 으로 표현됨. 0부터 1까지이며, 생략 시 1이 되고, q값이 클수록 우선순위가 높음.

```
Accept-Language: ko-KR,ko;q=0.9,en-US;q=0.8,en;q=0.7
Accept: text/html,application/xml;q=0.9,text/plain;q=0.6,*/*;q=0.5
```

### 보안: SSL/TLS와 HTTPS

**HTTPS(HTTP over SSL/TLS, HTTP Secure)** 는 HTTP에 SSL 혹은 TLS 프로토콜의 동작이 추가된 프로토콜임. 자물쇠 아이콘은 SSL/TLS 기반 암호화 통신이 이루어진다는 의미임.

- **SSL(Secure Sockets Layer)** 과 **TLS(Transport Layer Security)** 는 모두 인증과 암호화를 수행하는 프로토콜로, TLS는 SSL을 계승함.
- 오늘날 주로 사용되는 것은 TLS 1.2와 1.3이며, TLS 1.3의 비중이 커지고 있음.

**TLS 1.3 기반 HTTPS 메시지 송수신 단계**

1. **TCP 쓰리 웨이 핸드셰이크**
2. **TLS 핸드셰이크**
3. **암호화된 메시지 송수신**

**TLS 핸드셰이크의 핵심**

- **암호화 통신을 위한 키 생성/교환**: 평문 암호화·암호문 복호화에 필요한 **키**를 생성/교환. 키는 통신하는 두 호스트만 알고 있어야 함.
- **인증서 송수신과 검증**

**주요 메시지**

| 메시지 | 설명 |
|---|---|
| **ClientHello** | 지원 TLS 버전, 사용 가능한 암호화 알고리즘·해시 함수(**암호 스위트, cipher suite**), 클라이언트 난수 등 제시 |
| **ServerHello** | 제시된 정보 중 선택. 선택된 TLS 버전, 암호 스위트, 서버 난수 등 포함 |
| **Certificate** | 인증서 서명 값 등 인증서 내용 포함 |
| **CertificateVerify** | 인증서의 내용이 올바른지 검증 |
| **Finished** | TLS 핸드셰이크의 마지막을 의미 |

- **인증서(공개 키 인증서, public key certificate)**: '통신 상대방이 틀림없이 의도한 대상이 맞다'는 사실을 입증하기 위한 정보임. 제3의 **인증 기관(CA, Certificate Authority)** 이 발급/검증/저장함.
- 이후부터는 TLS 핸드셰이크로 얻어낸 키를 기반으로 암호화된 데이터를 주고받음.
