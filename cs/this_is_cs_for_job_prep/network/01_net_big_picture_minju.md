## 1. 네트워크의 큰 그림

### 네트워크의 기본 구조

네트워크는 **노드**와 **간선**으로 이루어진 자료구조라는 점에서 **그래프**의 형태를 띰. 네트워크 기기가 노드이고, 네트워크 기기 간에 정보를 주고받는 유무선의 통신 매체가 간선인 셈임.

- 노드와 노드 사이의 연결 구조는 **네트워크 토폴로지(network topology)** 라고 부름.
- 노드가 어떻게 연결/배치되느냐에 따라 **망형, 트리형, 링형, 성형, 버스형(선형)** 등의 유형으로 나뉨.
- 네트워크 가장자리에 위치하면서 정보를 최초로 송신하고 최종 수신하는 노드를 **호스트(host)** 라고 부름. 우리가 흔히 접하는 대부분의 네트워크 기기가 호스트임.

| 용어 | 설명 |
|---|---|
| **클라이언트(client)** | 요청(request)을 보내는 호스트 |
| **서버(server)** | 응답(response)을 보내는 호스트 |

- 클라이언트와 서버는 주고받는 정보의 방향(요청/응답)에 따라 부여된 역할임.
- 네트워크를 그래프로 볼 때 중간에 위치한 **중간 노드**는 가장자리 호스트가 주고받는 정보를 원하는 수신지까지 안정적으로 전송하는 역할을 함. (예: **스위치, 라우터, 공유기**)

#### LAN과 WAN

| 구분 | 의미 | 특징 |
|---|---|---|
| **LAN(Local Area Network)** | 근거리 네트워크 | 가정이나 기업처럼 비교적 가까운 거리를 연결하는 한정된 공간에서의 네트워크. 공유기를 기준으로 구축되는 경우가 많음 |
| **WAN(Wide Area Network)** | 원거리 네트워크 | LAN 간 통신이 이루어지는 네트워크. 인터넷을 가능하게 함. 일반적으로 **ISP(Internet Service Provider)** 가 구축/관리 (국내: KT, LG유플러스, SK브로드밴드) |

#### 패킷 교환 네트워크

네트워크를 통해 주고받는 데이터는 한 번에 송수신되지 않고, 여러 데이터로 쪼개져서 송수신됨. 이렇게 송수신되는 데이터의 단위를 **패킷(packet)** 이라고 함. 오늘날의 네트워크는 패킷 단위로 쪼개 송수신하고 수신지에서 재조립하는 '패킷 교환 네트워크'가 대부분임.

- 하나의 패킷은 **페이로드(payload)** 와 **헤더(header)** 로 구성되며, 때로는 **트레일러(trailer)** 가 포함되기도 함.
- 페이로드: 송수신하려는 데이터
- 헤더/트레일러: 패킷에 추가되는 부가 정보

#### 주소의 개념과 전송 방식

**주소(address)** 는 패킷의 헤더에 명시되는 정보로, 대표적인 주소로는 **IP 주소**와 **MAC 주소**가 있음.

| 전송 방식 | 설명 |
|---|---|
| **유니캐스트(unicast)** | 송신지와 수신지가 일대일로 메시지를 주고받는 방식 |
| **브로드캐스트(broadcast)** | 네트워크상의 모든 호스트에게 메시지를 전송하는 방식 |
| **멀티캐스트(multicast)** | 네트워크 내 동일 그룹에 속한 호스트에게만 전송 |
| **애니캐스트(anycast)** | 동일 그룹 호스트 중 가장 가까운 호스트에게 전송 |

- 브로드캐스트가 전송되는 범위를 **브로드캐스트 도메인(broadcast domain)** 이라고 하며, 같은 브로드캐스트 도메인에 속하면 같은 LAN에 속해 있다고 간주함.

### 두 호스트가 패킷을 주고받는 과정

#### 프로토콜

**프로토콜(protocol)** 은 네트워크에서 통신을 주고받는 노드 간의 합의된 규칙이나 방법을 말함. 호스트와 네트워크 장비들이 서로 정보를 이해하려면 같은 프로토콜을 이해하고 같은 프로토콜로 통신해야 함.

- 프로토콜마다 **목적**과 **특징**이 다름.
- 예: IP는 네트워크 간 **주소를 지정**, ARP는 **IP 주소와 MAC 주소를 대응**, HTTPS는 HTTP보다 **안전**, TCP는 UDP보다 **신뢰성**이 높음.

#### 네트워크 참조 모델

통신이 이루어지는 단계를 계층적으로 표현한 것을 **네트워크 참조 모델(network reference model)** 이라고 함. 패킷을 송신하는 쪽은 상위 계층에서 하위 계층으로 정보를 보내고, 수신하는 쪽은 하위 계층에서 상위 계층으로 정보를 받아들임.

- **OSI 모델**: 국제 표준화 기구(ISO)가 만든 참조 모델로, 통신 단계를 7개 계층으로 나눠 **OSI 7계층**이라고 부름.

| 계층 | 역할 |
|---|---|
| **물리 계층(physical layer)** | 가장 최하위 계층. 비트 신호(0과 1)를 유무선 통신 매체를 통해 운반 |
| **데이터 링크 계층(data link layer)** | 같은 LAN에 속한 호스트끼리 올바르게 정보를 주고받기 위한 계층. MAC 주소 사용, 오류 확인 |
| **네트워크 계층(network layer)** | 네트워크 간 통신을 가능하게 하는 계층. IP 주소 사용. 대표 프로토콜은 IP |
| **전송 계층(transport layer)** | 신뢰성 있는 전송, 포트를 통한 응용 프로그램 연결. 대표 프로토콜은 TCP, UDP |
| **세션 계층(session layer)** | 응용 프로그램 간의 연결 상태(세션)를 관리하기 위한 계층 |
| **표현 계층(presentation layer)** | 번역가 역할. 인코딩, 압축, 암호화 수행 |
| **응용 계층(application layer)** | 사용자와 가장 밀접한 계층. 대표 프로토콜은 HTTP, HTTPS, DNS 등 |

- **TCP/IP 모델**: TCP/IP 4계층이라고도 불리며, **네트워크 액세스 계층 / 인터넷 계층 / 전송 계층 / 응용 계층**으로 구성됨. OSI 모델은 이론적 기술, TCP/IP 모델은 구현과 프로토콜에 중점을 둠.
  - 네트워크 액세스 계층(= 링크 계층, 네트워크 인터페이스 계층)은 OSI의 데이터 링크 계층과 유사함.
  - 인터넷 계층은 OSI의 네트워크 계층, 전송 계층은 OSI의 전송 계층, 응용 계층은 OSI의 세션/표현/응용 계층을 합친 것과 유사함.

#### 캡슐화와 역캡슐화

| 용어 | 설명 |
|---|---|
| **캡슐화(encapsulation)** | 송신 과정에서 상위 계층의 패킷을 페이로드로 삼아 헤더(및 트레일러)를 추가해 나가는 과정 |
| **역캡슐화(decapsulation)** | 캡슐화 과정에서 붙인 헤더(및 트레일러)를 각 계층에서 확인한 뒤 제거하는 과정 |

계층마다 패킷(메시지)을 지칭하는 이름이 다름.

| 계층 | 패킷의 이름 |
|---|---|
| 그 이상의 계층 | 데이터(data) 또는 메시지(message) |
| 전송 계층 (TCP) | **세그먼트(segment)** |
| 전송 계층 (UDP) | **데이터그램(datagram)** |
| 네트워크 계층 | 패킷(IP 패킷) 또는 데이터그램 |
| 데이터 링크 계층 | **프레임(frame)** |
| 물리 계층 | 심볼(symbol) 또는 비트(bit) |
