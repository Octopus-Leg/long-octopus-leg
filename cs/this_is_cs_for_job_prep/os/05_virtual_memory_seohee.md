# 3.5 가상 메모리

## 물리 주소와 논리 주소
- **물리 주소**: 메모리의 하드웨어 상 실제 주소임.
- **논리 주소**: 프로세스마다 부여되는 0번지부터 시작되는 주소 체계임.
- `MMU`가 CPU와 메모리 사이에 위치하며, CPU가 이해하는 논리 주소를 메모리가 이해하는 물리 주소로 변환함.

## 스와핑과 연속 메모리 할당
### 스와핑
- **스와핑**: 현재 사용되지 않는 프로세스들을 보조기억장치의 일부 영역으로 쫓아내고, 프로세스를 쫓아낸 자리에 생긴 메모리 상의 빈 공간에 다른 프로세스를 적재하여 실행하는 메모리 관리 방식임.
- **스왑 아웃**: 현재 실행되지 않는 프로세스가 메모리에서 스왑 영역으로 옮겨지는 것을 말함.
- **스왑 인**: 스왑 영역에 있는 프로세스가 다시 메모리로 옮겨지는 것을 말함.
- 스왑 아웃된 프로세스가 다시 스왑 인될 때는 스왑 아웃되기 전의 물리 주소와는 다른 주소에 적재될 수 있음.

### 연속 메모리 할당과 외부 단편화
- **연속 메모리 할당**: 프로세스에 연속적인 메모리 공간을 할당함. 외부 단편화라는 문제를 내포해서 효율적인 방법은 아님.
- **외부 단편화**: 프로세스의 실행 및 종료를 반복하면서 메모리 사이에 빈 공간이 생기는데 그보다 큰 프로세스를 적재하기 어려워 메모리 낭비가 되는 현상을 말함.


## 페이징을 통한 가상 메모리 관리
- 외부 단편화와 물리 메모리보다 큰 프로세스를 실행할 수 없다는 문제를 해결하기 위해 나온 기술이 가상 메모리임.
- **가상 메모리**: 실행하고자 하는 프로그램의 일부만 메모리에 적재해 실제 메모리보다 더 큰 프로세스를 실행할 수 있도록 만드는 메모리 관리 기법임.
  - 보조기억장치의 일부를 메모리처럼 사용하거나 프로세스의 일부만 메모리에 적재함으로써 메모리를 실제 크기보다 더 크게 보이게 하는 기술임.
  - 가상 메모리 관리 기법에는 페이징과 세그멘테이션이 있음.

### 페이징과 세그멘테이션
- **페이징**
  - 프로세스의 논리 주소 공간을 페이지로 나누고, 물리 주소 공간을 페이지와 동일한 크기의 프레임이라는 일정한 단위로 나눈 뒤 페이지를 프레임에 할당하는 기법임.
  - 프로세스를 구성하는 페이지는 물리 메모리 내에 불연속적으로 배치될 수 있음.
  - 프로세스 바깥에 빈 공간이 생길 수 없어서 외부 단편화가 발생하지 않음.
  - 페이징 기법에도 스와핑이 사용될 수 있고, 스왑 아웃은 페이지 아웃, 스왑 인은 페이지 인이라고 함.
- **세그멘테이션**
  - 일정한 페이지 단위가 아닌 가변적인 크기의 세그먼트 단위로 분할하는 방식임. 세그먼트 크기가 일정하지 않아서 외부 단편화가 발생함.


### 페이지 테이블
- 페이지는 물리 메모리 내에 불연속적으로 배치되어 있어서 CPU가 프로세스를 이루는 페이지가 어떤 프레임에 적재되어 있는지를 모두 알기 어려움.
- 이런 문제를 해결하기 위해 프로세스의 페이지와 실제로 적재된 프레임을 짝지어주는 정보인 페이지 테이블을 활용함.
- 페이지 테이블에는 페이지 번호와 실제로 적재된 프레임 번호가 대응되어 있음.
- 페이지 테이블을 구성하고 있는 각각의 행들을 페이지 테이블 엔트리라고 부름.



#### 페이지 테이블 엔트리의 구성 요소
| 비트 종류 | 특징                                                                                                                                                                                                      |
| :--- |:--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **유효 비트** | 해당 페이지에 접근이 가능한지 여부를 알려주는 정보임.<br>현재 페이지가 메모리, 보조기억장치에 적재되어 있는지 알려주는 비트이며 메모리에 적재되어 있으면 1, 적재되어 있지 않으면 0임.<br>**유효 비트가 0인 페이지에 접근하려고 하면 페이지 폴트라는 예외가 발생함.** ➡️ 작업 내역 백업 후 페이지를 메모리로 로드하고 유효 비트를 1로 수정함. |
| **보호 비트** | 페이지 보호 기능을 위해 존재하는 비트임. rwx의 조합으로 100이면 읽기만 가능, 111이면 읽기 쓰기 실행 모두 가능함.                                                                                                                                  |
| **참조 비트** | CPU가 해당 페이지에 접근한 적이 있는지 여부를 나타내는 비트임. 접근된 적이 있으면 1로, 접근된 적이 없으면 0임.                                                                                                                                     |
| **수정 비트**<br>(더티 비트) | 해당 페이지에 데이터를 쓴 적이 있는지 여부를 나타내는 비트임. 1이면 변경된 적이 있는 페이지고, 0이면 변경된 적 없는 페이지임.<br>➡️ **수정 비트가 1이면 페이지를 메모리에서 삭제할 때 페이지의 수정 내역을 보조기억장치에도 반영해둬야 함.** 반대로 0일 때는 보조기억장치에 별도 쓰기 없이 삭제하면 됨.                       |

> **내부 단편화**: 프로세스 크기가 페이지의 배수로 나눠 떨어지지 않아서 페이지 하나의 크기보다 작은 크기로 발생하게 되는 메모리 낭비를 말함.

#### 페이지 테이블 관리의 두 가지 문제와 해결책
각 프로세스의 페이지 테이블은 메모리에 적재될 수 있어서 프로세스를 실행하려면 페이지 테이블이 적재된 위치를 알아야 하고, 이 위치를 가리키는 레지스터가 페이지 테이블 베이스 레지스터(PTBR)임. PTBR은 프로세스마다 가지는 정보이므로 각 PCB에 기록되며 다른 프로세스의 문맥 교환이 발생할 때 변경됨. 페이지 테이블을 메모리에 두는 것은 메모리 접근 횟수가 많아지고 메모리 용량을 많이 차지하기 때문에 비효율적이라서 모든 페이지 테이블을 메모리에 적재하는 것을 지양함.

- **1. 메모리 접근 횟수 문제**
  - **원인**: 페이지 테이블에 접근하기 위해 한 번, 실제 프레임에 접근하기 위해 한 번 총 두 번 메모리에 접근해야 하므로 비효율적임.
  - **해결책**: `TLB`라는 페이지 테이블 캐시 메모리를 사용함. TLB는 페이지 테이블의 캐시이므로 참조 지역성의 원리에 근거해 자주 사용될 법한 페이지 위주로 페이지 테이블의 일부 내용을 저장함.
    - **TLB 히트**: CPU가 접근하려는 페이지 번호가 TLB에 있는 경우 TLB가 CPU에게 해당 페이지 번호가 적재된 프레임 번호를 알려줌.
    - **TLB 미스**: 페이지 번호가 TLB에 없는 경우에 페이지 테이블에 접근하는 경우임.
- **2. 메모리 용량 문제**
  - **원인**: 모든 페이지 테이블 엔트리들을 메모리에 두는 것은 공간 낭비임.
  - **해결책**: **계층적 페이징** 방식을 도입함. 모든 페이지 테이블 엔트리들을 메모리에 두는 것은 낭비라서 페이지 테이블을 페이징하는 방식으로, 여러 단계의 페이지를 둠.

### 페이징 주소 체계
- 페이징 시스템의 논리 주소는 기본적으로 `<페이지 번호, 변위>`와 같은 형태로 이루어져 있음.
  - **페이지 번호**: 몇 번째 페이지 번호에 접근할지를 나타냄.
  - **변위**: 접근하려는 주소가 페이지 시작 번지로부터 얼만큼 떨어져 있는지 나타내는 정보임.
- `<페이지 번호, 변위>`로 이루어진 논리 주소는 페이지 테이블을 통해 물리 주소인 `<프레임 번호, 변위>`로 변환됨.


## 페이지 교체 알고리즘
- 메모리에 적재된 페이지 중 보조기억장치로 내보낼 페이지를 선택하는 방법을 말함. 좋은 페이지 교체 알고리즘을 써야 페이지 폴트의 발생 빈도를 줄일 수 있음.

- **FIFO 페이지 교체 알고리즘**
  - 메모리에 가장 먼저 적재된 페이지부터 스왑 아웃하는 페이지 교체 알고리즘임.
- **최적 페이지 교체 알고리즘**
  - 가장 적게 사용될 페이지를 스왑 아웃해 가장 낮은 페이지 폴트율을 보장하는 알고리즘이지만 실제 구현이 어려움.
- **LRU 페이지 교체 알고리즘**
  - 가장 적게 사용한 페이지를 교체하는 알고리즘임.
