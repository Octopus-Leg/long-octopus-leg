## 6. 파일 시스템

- **파일 시스템(file system)**: 보조기억장치의 정보를 파일 및 디렉터리 형태로 저장하고 관리하는 운영체제 내부 프로그램
- 한 운영체제 내에서도 여러 파일 시스템을 사용할 수 있으며, 파일 시스템마다 정보를 다루는 방식이 다름.

### 파일과 디렉터리

#### 파일(file)
- 파일 이름 + 파일을 실행하기 위한 정보 + 파일 관련 부가 정보(**속성/메타데이터**)로 구성됨.
- 파일과 관련된 모든 작업은 운영체제가 시스템 콜을 통해 수행함.
- **파일 디스크립터(file descriptor)**: 운영체제가 열린 파일을 식별하기 위해 프로세스에 할당하는 0 이상의 정수값
  - 리눅스에서는 파일뿐 아니라 입출력장치, 파이프, 소켓도 파일 디스크립터로 식별함.

| 파일 디스크립터 | 할당 |
|---|---|
| 0 | 표준 입력 |
| 1 | 표준 출력 |
| 2 | 표준 에러 |

#### 디렉터리(directory)
- 오늘날 디렉터리는 **트리 구조(tree-structured directory)** 로 관리됨.
- **루트 디렉터리**: 최상위 디렉터리. 리눅스/맥OS는 `/`, 윈도우는 `C:\`
- **경로(path)**: 루트 디렉터리로부터 파일 위치를 특정하는 정보
- 디렉터리도 일종의 파일로 간주하며, 내부 요소의 관련 정보를 테이블 형태로 저장함.
- 테이블의 행 하나하나를 **디렉터리 엔트리(directory entry)** 라 하며, 파일 이름과 저장 위치 정보를 포함함.
  - `..`: 상위 디렉터리, `.`: 현재 디렉터리

#### 파일 할당 (블록 단위)
- 운영체제는 파일과 디렉터리를 **블록(block)** 단위(보통 4096바이트)로 읽고 씀.

| 방식 | 설명 |
|---|---|
| **연결 할당(linked allocation)** | 각 블록에 다음 블록 주소를 저장함. 디렉터리 엔트리에 첫 블록 주소가 명시됨 |
| **색인 할당(indexed allocation)** | 모든 블록 주소를 **색인 블록**에 모아 관리함. 디렉터리 엔트리에 색인 블록 주소가 명시됨 |

### 파일 시스템

#### 대표적인 파일 시스템

| OS | 파일 시스템 |
|---|---|
| 윈도우 | NTFS, ReFS |
| 리눅스 | EXT, EXT2, EXT3, EXT4, XFS, ZFS |
| 맥OS | APFS |

- **파티션(partition)**: 보조기억장치 내 파일 시스템을 적용할 영역. 파티션마다 다른 파일 시스템 사용할 수 있음.
- **포매팅(formatting)**: 파일 시스템을 설정하고 데이터를 쓸 준비를 하는 작업

#### 아이노드(inode) 기반 파일 시스템
- EXT4, XFS, ZFS 등 리눅스 계열 파일 시스템에서 사용됨.
- 각 파일마다 고유의 **아이노드 번호**를 부여받으며, 아이노드에는 파일 이름을 제외한 사실상 모든 파일 정보(위치, 속성 등)가 담김.
- 아이노드 영역이 가득 차면 데이터 영역에 공간이 남아 있어도 새 파일을 생성할 수 없음.

#### 하드 링크와 심볼릭 링크

| 종류 | 설명 |
|---|---|
| **하드 링크(hard link)** | 원본과 같은 아이노드를 공유하는 파일. 원본 파일이 삭제되거나 이동해도 파일 데이터에 접근 가능함 |
| **심볼릭 링크(symbolic link)** | 원본 파일의 경로를 저장한 별개의 파일. 원본 삭제 시 사용이 불가능함 |

#### 마운트(mount)
- 다른 저장장치의 파일 시스템을 현재 파일 시스템의 특정 경로에 편입시키는 작업
- 예: USB를 `/mnt`에 마운트하면 `/mnt/...` 경로로 USB 파일에 접근할 수 있음.
