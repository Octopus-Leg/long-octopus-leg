## 5. 가상 메모리

### 물리 주소와 논리 주소
- **물리 주소(physical address)**: 메모리 하드웨어 상의 실제 주소로 중복될 수 없음.
- **논리 주소(logical address)**: 프로세스마다 부여되는 0번지부터 시작하는 독립적인 주소 체계로 중복될 수 있음.
- CPU와 프로세스는 논리 주소를 사용하며, **메모리 관리 장치(MMU)** 가 이를 물리 주소로 변환함.

### 스와핑과 연속 메모리 할당
- **스와핑(swapping)**: 오래 사용되지 않은 프로세스를 보조기억장치의 **스왑 영역**으로 내보내고, 그 자리에 다른 프로세스를 적재해 메모리를 확보하는 기법
  - **스왑 아웃**: 메모리 → 스왑 영역
  - **스왑 인**: 스왑 영역 → 메모리 (이전과 다른 물리 주소에 적재될 수 있음)
- **연속 메모리 할당**: 프로세스에 메모리 주소를 연속적으로 할당하는 방식
- **외부 단편화(external fragmentation)**: 빈 공간들의 총합은 충분하지만 공간이 흩어져 있어 큰 프로세스를 적재하지 못하는 메모리 낭비 현상

### 페이징을 통한 가상 메모리 관리
- **가상 메모리(virtual memory)**: 프로그램 일부만 메모리에 적재해 실제 메모리보다 큰 프로세스를 실행할 수 있게 하는 메모리 관리 기법
- **페이징(paging)**: 논리 주소 공간을 **페이지**, 물리 주소 공간을 동일 크기의 **프레임** 단위로 나눠 페이지를 프레임에 할당하는 방식
  - 페이지를 불연속적으로 배치할 수 있어 외부 단편화를 해결함.
  - **내부 단편화**: 프로세스 크기가 페이지 크기의 배수가 아닐 때 마지막 페이지에 남는 메모리 낭비

#### 페이지 테이블(page table)
- 페이지 번호와 프레임 번호를 매핑하는 정보로, 프로세스마다 각자의 페이지 테이블을 가짐.

| 페이지 테이블 엔트리 항목 | 설명 |
|---|---|
| 유효 비트(valid bit) | 페이지가 메모리에 있으면 1, 스왑 영역에 있으면 0 |
| 보호 비트(protection bit) | 페이지 접근 권한 (읽기/쓰기/실행) |
| 참조 비트(reference bit) | CPU가 접근한 적 있는지 여부 |
| 수정 비트(dirty bit) | 데이터를 쓴 적 있는지 여부 |

- **페이지 폴트(page fault)**: 유효 비트가 0인 페이지에 접근할 때 발생하는 예외. OS가 해당 페이지를 메모리에 적재함.

**TLB(Translation Look-aside Buffer)**
- 페이지 테이블의 캐시로, 자주 사용하는 페이지 번호 → 프레임 번호 매핑을 저장함.
- **TLB 히트**: TLB에서 바로 프레임 번호를 찾아 메모리 1회 접근으로 해결함.
- **TLB 미스**: TLB에 없어 메모리의 페이지 테이블까지 추가 접근이 필요함.

### 페이지 교체 알고리즘
- **요구 페이징(demand paging)**: 필요한 페이지만 메모리에 적재하는 기법
- **페이지 교체 알고리즘**: 메모리가 가득 찼을 때 어떤 페이지를 스왑 아웃할지 결정하는 방법

| 알고리즘 | 설명 | 특징 |
|---|---|---|
| **FIFO** | 가장 먼저 적재된 페이지부터 교체하는 알고리즘 | 구현이 간단함, 자주 쓰이는 페이지도 교체될 수 있음 |
| **최적(Optimal)** | 앞으로 가장 적게 사용할 페이지 교체하는 알고리즘 | 가장 낮은 페이지 폴트율, 실제 구현이 불가능함 |
| **LRU** | 가장 오래 사용되지 않은 페이지 교체하는 알고리즘 | 현실적으로 가장 널리 사용됨 |

- **스래싱(thrashing)**: 실제 실행 시간보다 페이지 교체에 더 많은 시간을 소요해 성능이 급격히 저하되는 현상. 지나친 페이지 교체가 원인임.
