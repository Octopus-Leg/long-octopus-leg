# 3.2 프로세스와 스레드

### 프로세스 유형
- **포그라운드 프로세스**: 사용자가 보는 공간에서 사용자와 상호작용하며 실행되는 프로세스임.
- **백그라운드 프로세스**: 사용자가 보지 못하는 곳에서 실행되는 프로세스임.
  - **데몬**: 백그라운드 프로세스 중 하나로 사용자와 상호작용 없이 주어진 작업만 수행하는 프로세스임. 윈도우에서는 서비스라고 부름.

### 메모리 내 프로세스 정보
- **커널 영역**: 프로세스 제어 블록으로 저장됨.
- **사용자 영역**: 실행 중인 프로세스가 코드 영역, 데이터 영역, 힙 영역, 스택 영역으로 나뉘어 저장됨.
  - **정적 할당 영역**: 실행 도중 크기가 변하지 않는 코드 영역과 데이터 영역임.
    - **코드 영역**(= 텍스트 영역): 실행 가능한 명령어가 저장되는 공간이며, 쓰기가 금지되어 있는 읽기 전용 공간임.
    - **데이터 영역**: 프로그램이 실행되는 동안 유지할 데이터가 저장되는 공간으로, 주로 정적 변수나 전역 변수가 저장됨.
  - **동적 할당 영역**: 실행 도중 크기가 변할 수 있는 영역임.
    - **힙 영역**: 사용자가 직접 할당 가능한 저장 공간임.
      - 메모리 공간을 반환하지 않으면 할당한 공간이 메모리 내에 남아 메모리를 낭비하는 `메모리 누수` 문제를 초래할 수 있음.
      - `메모리 누수` 문제를 해결하기 위해 프로그래밍 언어에서 자체적으로 사용하지 않는 힙 메모리를 해제하는 `가비지 컬렉션` 기능을 제공함.
    - **스택 영역**: 일시적으로 사용할 값들이 저장되는 공간임. 대표적으로 매개변수, 지역변수, 함수 복귀 주소 등이 저장됨.
      - 스택 영역에는 `스택 트레이스` 형태의 함수 호출 정보가 저장될 수 있고, 문제의 발생 지점을 추적할 수 있게 함.

### PCB와 문맥 교환
- 다수의 프로세스를 관리하기 위해서는 프로세스를 식별할 수 있는 커널 영역 내 정보가 필요하고, 이것을 `PCB`라고 함.
- `PCB`는 새로운 프로세스가 메모리에 적재됐을 때 커널 영역에 만들어지고, 프로세스의 실행이 끝나면 폐기됨.
- **`PCB`에 저장되는 정보**
  - 프로세스 ID, 실행 과정에서 사용한 레지스터 값, 프로세스 상태, CPU 스케줄링 정보, 메모리 관련 정보, 파일 및 입출력장치 관련 정보임.
- 여러 `PCB`들은 커널 내에 프로세스 테이블의 형태로 관리되는 경우가 많음.
- 일반적으로 메모리에 적재된 프로세스들은 한정된 시간 동안 번갈아 가며 실행되고, 운영체제에 의해 CPU의 자원을 할당받음.
- 프로세스의 CPU 사용시간은 `타이머 인터럽트`에 의해 제한됨. `타이머 인터럽트`란 시간이 끝났음을 알리는 인터럽트임.
- `타이머 인터럽트`가 발생하면 실행 중이던 프로세스는 지금까지의 중간 정보인 `문맥`을 `PCB`에 저장함. 그리고 뒤이어 실행할 프로세스의 `문맥`을 복구함.
- 위의 과정처럼 기존 프로세스의 `문맥`을 `PCB`에 백업하고, `PCB`에서 `문맥`을 복구하여 새로운 프로세스를 실행하는 것을 `문맥 교환`이라고 함.
- `문맥 교환`이 너무 자주 일어나면 `캐시 미스`가 발생할 가능성이 높아져 큰 `오버헤드`로 이어질 수 있음.

### 프로세스의 상태
- **생성, 준비, 실행, 대기, 종료** 상태가 있음.
- **생성**: 프로세스를 생성 중인 상태로, `PCB`를 할당받은 상태임.
- **준비**: 당장이라도 CPU를 할당받아 실행할 수 있지만, 차례가 아니라서 기다리고 있는 상태임. 준비 상태인 프로세스가 실행 상태로 전환되는 것을 `디스패치`라고 함.
- **실행**: CPU를 할당받아 실행 중인 상태임. `타이머 인터럽트`가 발생하면 다시 준비 상태가 되고, 실행 도중 입출력장치의 작업이 끝날 때까지 기다려야 하면 대기 상태가 됨.
- **대기**: 곧장 실행이 불가능한 조건에 놓이는 경우 대기 상태가 됨. 입출력 작업을 요청하는 경우가 대표적임. 입출력 작업이 완료되면 다시 준비 상태가 되어 CPU 할당을 기다림.
- **종료**: 프로세스가 종료된 상태임. 프로세스가 종료되면 운영체제는 `PCB`와 프로세스가 사용한 메모리를 정리함.

## 멀티프로세스와 멀티스레드
- 웹 브라우저는 일반적으로 하나의 탭마다 하나의 프로세스로 동작함. 이렇게 동시에 여러 프로세스가 실행되는 것을 `멀티프로세스`라고 함.
- `멀티프로세스`에서는 각각의 프로세스들이 자원을 공유하지 않고 독립적으로 실행됨. 그래서 한 프로세스에 문제가 발생하더라도 다른 프로세스에 직접적인 영향을 끼치지 않음.
- 프로세스를 동시에 실행하는 여러 스레드를 `멀티스레드`라고 함. 하나의 스레드는 스레드를 식별할 수 있는 고유 정보인 스레드 ID와 프로그램 카운터, 레지스터 값, 스택 등으로 구성됨.
- 스레드마다 각각 프로그램 카운터 값과 스택을 가지고 있어서 스레드마다 다음에 실행할 주소를 가질 수 있고, 연산 과정의 임시 저장 값을 가질 수 있음.
- 가장 큰 차이점은 자원의 공유 여부에 있음. 스레드끼리는 코드, 데이터, 힙 영역을 공유해서 한 스레드에 생긴 문제가 프로세스 전체의 문제가 될 수 있음.

## 프로세스 간 통신
- 프로세스 간에도 자원을 공유하고 데이터를 주고받는 방법을 `IPC`라고 함. 크게 공유 메모리와 메시지 전달 방법이 있음.

### 공유 메모리
- **공유 메모리**: 데이터를 주고받는 프로세스가 공통적으로 사용할 메모리 영역을 두는 방식임.
- 공유 메모리 기반 IPC는 프로세스가 공유하는 메모리 영역을 확보하는 시스템 콜 기반으로 수행될 수도 있고, 프로세스가 공유하는 변수나 파일을 활용할 수도 있음.
- 각 프로세스가 마치 자신의 메모리 영역을 읽고 쓰는 것처럼 통신한다는 점이 특징임. 또한, 프로세스가 데이터를 주고받는 과정에 커널의 개입이 거의 없음.
- 메시지 전달 방식보다 통신 속도가 빠르지만, 각각의 프로세스가 서로의 공유 메모리 영역을 동시에 읽고 쓸 경우 데이터의 일관성이 훼손되는 `레이스 컨디션`이 발생할 수 있음.

### 메시지 전달
- **메시지 전달**: 프로세스 간에 주고받을 데이터를 메시지의 형태로 주고받는 방식임.
- 커널을 거쳐 송수신하기 때문에 `레이스 컨디션`, 동기화 등의 문제를 고려하는 일이 적음. 대신 **공유 메모리 기반 IPC보다 속도가 느림.**
- 대표적인 수단으로 파이프, 시그널, 소켓, 원격 프로시저 호출 등이 있음.
  - **파이프**: 단방향 프로세스 간의 통신 도구로, 파이프로 양방향 통신을 수행할 경우 읽기용 파이프와 쓰기용 파이프 2개를 이용해 통신함.
  - **시그널**: 프로세스에게 특정 이벤트가 발생했음을 알리는 비동기적인 신호임. 시그널이 발생하면 시그널 처리를 위한 `시그널 핸들러`를 실행한 뒤 실행을 재개함.
    - 직접적으로 메시지를 주고받지는 않지만, 비동기적으로 원하는 동작을 수행할 수 있는 좋은 수단임.
  - **원격 프로시저 호출(RPC)**: 원격 코드를 실행하는 IPC 기술임.
