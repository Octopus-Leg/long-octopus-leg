## 4. CPU 스케줄링

- **CPU 스케줄링(CPU scheduling)**: 운영체제가 프로세스/스레드에 CPU 사용을 배분하는 방법
- **CPU 스케줄러(CPU scheduler)**: CPU 스케줄링 알고리즘을 결정·수행하는 운영체제 일부분

#### 우선순위(priority)

- 프로세스마다 우선순위를 부여하고 PCB에 명시함.
- 운영체제는 기본적으로 입출력 작업이 많은 프로세스의 우선순위를 높게 유지함. (CPU 활용률 극대화 목적)

| 구분 | 설명 |
|---|---|
| CPU 버스트(CPU burst) | 프로세스가 CPU를 이용하는 작업 |
| 입출력 버스트(I/O burst) | 프로세스가 입출력장치를 기다리는 작업 |
| CPU 집중 프로세스(CPU bound process) | CPU 버스트가 긴 프로세스 (예: 복잡한 수학 연산, 그래픽 처리) |
| 입출력 집중 프로세스(I/O bound process) | 입출력 버스트가 긴 프로세스 (예: 비디오 재생, 디스크 백업) |

#### 스케줄링 큐(scheduling queue)

- 자원을 이용하고 싶은 프로세스들의 PCB가 서는 줄
- **준비 큐(ready queue)**: CPU를 이용하고 싶은 PCB의 줄
- **대기 큐(waiting queue)**: 대기 상태에 접어든 PCB의 줄. 같은 입출력장치를 요구한 PCB끼리 같은 대기 큐에서 대기
- 운영체제마다 다양한 종류의 큐를 관리함.

#### 선점형 스케줄링 vs 비선점형 스케줄링

| 구분 | 설명 | 장단점 |
|---|---|---|
| 선점형(preemptive) | 운영체제가 강제로 CPU를 빼앗아 다른 프로세스에 할당 | 한 프로세스의 CPU 독점 방지 / 문맥 교환 오버헤드 |
| 비선점형(non-preemptive) | 종료/대기 상태 전까지 CPU를 뺏을 수 없음 | 오버헤드 적음 / CPU 사용 중이면 무작정 대기 |

- 타이머 인터럽트 기반 스케줄링은 모두 선점형 스케줄링에 속함.

### CPU 스케줄링 알고리즘

#### 전통적 스케줄링 알고리즘 7가지

| 알고리즘 | 설명 | 비고 |
|---|---|---|
| 선입 선처리(FCFS) | 준비 큐 삽입 순서대로 처리 | **호위 효과(convoy effect)** 발생 가능 |
| 최단 작업 우선(SJF) | CPU 이용 시간이 가장 짧은 프로세스부터 처리 | 기본은 비선점형 |
| 라운드 로빈(round robin) | FCFS + **타임 슬라이스(time slice)**. 정해진 시간만큼 사용 후 큐 뒤로 | 선점형 |
| 최소 잔여 시간 우선(SRT) | SJF + 라운드 로빈. 타임 슬라이스 동안 실행하되 잔여 시간이 짧은 프로세스 선택 | 선점형 |
| 우선순위 스케줄링 | 우선순위 높은 프로세스부터 실행 | **아사(starvation)** 문제 → **에이징(aging)** 으로 보완 |
| 다단계 큐(multilevel queue) | 우선순위별 여러 개의 준비 큐 사용 | 큐 간 이동 불가 → 아사 발생 가능 |
| 다단계 피드백 큐(multilevel feedback queue) | 다단계 큐 + 큐 간 이동 가능 | CPU 집중 ↓ / 입출력 집중 ↑ 우선순위로 자연스럽게 정렬. 에이징도 적용 가능 |

- **호위 효과(convoy effect)**: 오랜 실행 시간으로 인해 나중에 삽입된 프로세스 실행이 지연되는 현상
- **아사(starvation)**: 우선순위 낮은 프로세스가 계속 실행 연기되는 현상
- **에이징(aging)**: 오래 대기한 프로세스의 우선순위를 점차 높이는 기법

### 리눅스 CPU 스케줄링

리눅스에서는 상황에 따라 다양한 스케줄링 알고리즘이 사용됨. 새로운 프로세스를 언제 어떻게 선택할지 결정하는 규칙의 집합을 **스케줄링 정책(scheduling policy)** 이라고 함.

#### 리눅스 스케줄링 정책 5가지

| 정책 | 적용 상황 |
|---|---|
| SCHED_FIFO | 실시간성 프로세스에 적용 (매우 높은 우선순위 할당) |
| SCHED_RR | 실시간성 프로세스에 적용 (매우 높은 우선순위 할당) |
| SCHED_NORMAL | 일반적인 프로세스에 적용 |
| SCHED_BATCH | 자주 선점되지 않는 배치 작업에 적용 |
| SCHED_IDLE | 우선순위가 매우 낮은 프로세스에 적용 (매우 낮은 우선순위 할당) |

#### CFS(Completely Fair Scheduler, 완전히 공정한 스케줄러)

- SCHED_NORMAL의 스케줄러로, '완전히 공평한 CPU 시간 배분'을 지향함.
- 프로세스마다 **가상 실행 시간(vruntime)** 을 유지하며, vruntime이 가장 작은 프로세스부터 스케줄링함.
- vruntime은 실제 실행 시간이 아니라 프로세스의 **가중치(weight)** 를 고려한 가상 실행 시간임.
