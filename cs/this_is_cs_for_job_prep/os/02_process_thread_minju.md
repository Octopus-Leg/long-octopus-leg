## 2. 프로세스와 스레드

프로세스의 정보는 커널 영역의 **PCB**와 사용자 영역의 **코드/데이터/힙/스택 영역**에 저장됨.

- **포그라운드 프로세스**: 사용자와 상호작용하며 실행되는 프로세스
- **백그라운드 프로세스**: 사용자와 직접 상호작용 없이 실행되는 프로세스
  - **데몬(daemon)** / **서비스(service)**: 백그라운드에서 주어진 작업만 수행하는 특별한 프로세스. 윈도우에서는 서비스라고 부름.

#### 사용자 영역의 4가지 메모리 영역

| 영역 | 설명 |
|---|---|
| 코드 영역 (텍스트 영역) | 실행 가능한 명령어가 저장되는 공간. 읽기 전용(read-only) |
| 데이터 영역 | 정적 변수·전역 변수가 저장되는 공간. 프로그램 실행 동안 유지 |
| 힙 영역 | 개발자가 직접 할당 가능한 저장 공간. 미해제 시 **메모리 누수(memory leak)** 발생 |
| 스택 영역 | 매개변수·지역 변수·함수 복귀 주소 등 일시적 데이터 저장되는 공간 |

- 코드/데이터 영역은 크기가 변하지 않아 **정적 할당 영역**, 힙/스택 영역은 크기가 변할 수 있어 **동적 할당 영역**이라고 부름.
- **스택 트레이스(stack trace)**: 특정 시점의 스택 영역에 저장된 함수 호출 정보. 디버깅에 유용함.

#### PCB와 문맥 교환

- **PCB(Process Control Block, 프로세스 제어 블록)**: 커널 영역에 만들어지는 프로세스를 식별하는 정보. 프로세스 생성 시 만들어지고 종료 시 폐기됨.
- PCB 주요 정보: PID, 프로세스 상태, CPU 스케줄링(우선순위) 정보, 메모리 관련 정보, 사용한 파일 및 입출력장치 정보, 실행 과정에서 사용한 레지스터 값
- **프로세스 테이블(process table)**: 실행 중인 PCB의 모음. 커널 내에 관리됨.
- **좀비 프로세스(zombie process)**: 비정상 종료되어 PCB가 프로세스 테이블에 남아 있는 프로세스
- **타이머 인터럽트(타임아웃 인터럽트)**: 정해진 시간 종료를 알리는 하드웨어 인터럽트. 프로세스의 CPU 사용 시간을 제한함.
- **문맥(context)**: 프로세스가 수행을 재개하기 위해 기억해야 할 중간 정보. PCB에 명시됨.
- **문맥 교환(context switching)**: 기존 프로세스의 문맥을 PCB에 백업하고, 다음 프로세스의 PCB에서 문맥을 복구해 실행하는 작업
- 너무 잦은 문맥 교환은 캐시 미스 발생 가능성을 높여 큰 오버헤드로 이어질 수 있음.

#### 프로세스 상태 다이어그램

| 상태 | 설명 |
|---|---|
| 생성(new) | 메모리에 적재되어 PCB를 할당받은 상태 |
| 준비(ready) | CPU 할당을 기다리는 상태. **디스패치(dispatch)** 로 실행 상태 전환 |
| 실행(running) | CPU 할당받아 실행 중. 타이머 인터럽트 → 준비 상태 / 입출력 요청 → 대기 상태 |
| 대기(blocked) | 입출력 작업 등 곧장 실행이 불가능한 상태 |
| 종료(terminated) | 프로세스 종료. PCB와 사용 메모리를 정리 |

> **블로킹 입출력 vs 논블로킹 입출력**
> - **블로킹 입출력**: 입출력 요청 후 완료까지 대기 상태에 접어듦.
> - **논블로킹 입출력**: 입출력을 맡긴 뒤 곧바로 다음 명령어 실행.

### 멀티프로세스와 멀티스레드

- **멀티프로세스(multi-process)**: 동시에 여러 프로세스가 실행되는 것. 같은 프로그램을 여러 번 실행해도 별도의 프로세스가 됨.
- **스레드(thread)**: 프로세스를 이루는 실행의 단위. 스레드 ID, 프로그램 카운터, 레지스터 값, 스택 등으로 구성됨.
- **멀티스레드(multi-thread)**: 하나의 프로세스를 구성하는 여러 스레드를 동시에 실행하는 것

#### 멀티프로세스 vs 멀티스레드

가장 큰 차이: **자원의 공유 여부**

| 구분 | 멀티프로세스 | 멀티스레드 |
|---|---|---|
| 자원 공유 | 공유하지 않음 (독립적 실행) | 같은 코드·데이터·힙 영역, 열린 파일 공유 |
| 통신 비용 | 큼 | 작음 |
| 한 단위의 문제 발생 시 | 다른 프로세스에 영향 거의 없음 | 다른 스레드까지 전체 영향 가능 |

- **스레드 조인(join)**: 스레드를 생성한 주체가 해당 스레드의 종료를 기다리도록 하는 기능

### 프로세스 간 통신

**프로세스 간 통신(IPC, Inter-Process Communication)**: 프로세스 간 자원을 공유하고 데이터를 주고받는 방법. 크게 2가지 유형이 있음.

| 방식 | 설명 | 특징 |
|---|---|---|
| **공유 메모리(shared memory)** | 프로세스가 공유하는 메모리 영역을 토대로 데이터를 주고받음 | 커널 개입 적음, 빠름, 레이스 컨디션 발생 가능 |
| **메시지 전달(message passing)** | 커널을 거쳐 메시지로 송수신 | 커널의 도움으로 동기화 문제 적음, 상대적으로 느림 |

#### 메시지 전달의 대표 수단

- **파이프(pipe)**: 단방향 프로세스 간 통신 도구. 양방향 통신은 읽기용·쓰기용 2개 활용
  - **익명 파이프(unnamed pipe)**: 양방향 통신 미지원, 부모-자식 프로세스 간만 가능
  - **지명 파이프(named pipe, FIFO)**: 양방향 통신 지원, 임의의 프로세스 간 통신 가능
- **시그널(signal)**: 프로세스에게 특정 이벤트 발생을 알리는 비동기 신호
- **소켓**: 네트워크 기반 IPC (네트워크 장에서 다룸)
- **원격 프로시저 호출(RPC, Remote Procedure Call)**: 원격 코드를 실행하는 IPC 기술. 대표적으로 구글의 gRPC.

#### 대표적인 시그널 종류 (리눅스)

| 시그널 | 설명 | 기본 동작 |
|---|---|---|
| SIGCHLD | 자식 프로세스 종료 | 무시 |
| SIGILL | 허용하지 않은 명령어 실행 | 코어 덤프 생성 후 종료 |
| SIGINT | 키보드 인터럽트(Ctrl+C) | 종료 |
| SIGKILL | 프로세스 종료(핸들러 재정의 불가능) | 종료 |
| SIGSEGV | 잘못된 메모리 접근 | 코어 덤프 생성 후 종료 |
| SIGTERM | 프로세스 종료(핸들러 재정의 가능) | 종료 |
| SIGUSR1, SIGUSR2 | 사용자 정의 시그널 | 종료 |

- **시그널 핸들러(signal handler)**: 시그널 처리를 위해 실행되는 함수. 직접 정의·재정의 가능.
- **코어 덤프(core dump)**: 비정상 종료 시 메모리 상태가 기록되는 파일. 디버깅 용도로 자주 활용됨.
