# 3.4 CPU 스케줄링
- **CPU 스케줄링**: 운영체제의 CPU 배분 방법임. `CPU 스케줄링 알고리즘`은 이러한 `CPU 스케줄링`의 절차를 말함.

### 우선순위
- 운영체제는 프로세스별 우선순위를 판단하여 `PCB`에 명시하고, 우선순위가 높은 프로세스에는 CPU의 자원을 더 빨리, 더 많이 할당함.
- 유닉스 체계의 운영체제에서는 `ps` 명령어를 통해 프로세스의 우선순위를 확인할 수 있음.
- 운영체제는 가급적 **CPU 활용률**을 높게 유지할 수 있도록 우선순위를 할당함.
- 높은 **CPU 활용률**을 유지하기 위해 기본적으로 입출력 작업이 많은 프로세스의 우선순위를 높게 유지함.
    - **CPU 활용률**: 전체 CPU의 가동 시간 중 작업을 처리하는 시간의 비율을 의미함.
- **`CPU 버스트`**: 프로세스가 CPU를 이용하는 작업임.
- **`입출력 버스트`**: 입출력장치를 기다리는 작업임.
- **`입출력 집중 프로세스`**: 비디오 재생이나 디스크 백업 작업을 담당하는 프로세스처럼 입출력 작업이 많은 프로세스임.
- **`CPU 집중 프로세스`**: 복잡한 수학 연산이나 그래픽 처리 작업을 담당하는 프로세스처럼 CPU 작업이 많은 프로세스임.
- `입출력 집중 프로세스`와 `CPU 집중 프로세스`가 동시에 CPU의 자원을 요구했다면 `입출력 집중 프로세스`를 가능한 빨리 실행시켜 입출력 장치를 가동한 다음, `CPU 집중 프로세스`에 집중적으로 CPU를 할당하는 것이 더 합리적임. 그래서 `입출력 집중 프로세스`는 일반적으로 `CPU 집중 프로세스`보다 우선순위가 높음.

### 스케줄링 큐
- 운영체제는 `스케줄링 큐`를 통해 프로세스에게 줄을 서서 기다리게 함.
- 대표적으로 `준비 큐`와 `대기 큐`가 있음.
- **`준비 큐`**: CPU를 이용하고 싶은 프로세스의 `PCB`가 서는 줄을 의미함. 준비 상태인 프로세스의 `PCB`는 `준비 큐`의 마지막에 삽입되어 CPU 사용 순서를 기다림.
- **`대기 큐`**: 대기 상태에 접어든 프로세스의 `PCB`가 서는 줄을 의미함. 주로 입출력 작업을 수행 중이면 `대기 큐`에서 대기 상태로 입출력 완료 인터럽트를 기다림.
- 운영체제는 큐에 삽입된 순서대로 실행하되, 우선순위가 높은 프로세스부터 먼저 실행함.
- 실행되는 프로세스가 할당받은 시간을 모두 사용하면 `준비 큐`로 다시 이동하고, 실행 도중 입출력 작업을 수행해 대기 상태로 접어들어야 할 경우 `대기 큐`로 이동함.
- 같은 입출력장치를 요구한 프로세스들은 같은 `대기 큐`에서 기다림. 예를 들어 `프린터 대기 큐`, `하드디스크 대기 큐` 등이 있음.

### 선점형 스케줄링과 비선점형 스케줄링
#### 선점형 스케줄링
- 실행 상태에서 입출력 작업을 위해 대기 상태로 전환될 때와 실행 상태에서 타이머 인터럽트가 발생해 준비 상태로 변경될 때의 상황에서 수행되는 스케줄링 유형임.
- 현재 어떤 프로세스가 CPU를 할당받아 사용하고 있더라도 운영체제가 프로세스로부터 CPU 자원을 강제로 빼앗아 다른 프로세스에 할당할 수 있는 스케줄링임.
- 따라서 타이머 인터럽트 기반 스케줄링은 모두 `선점형 스케줄링`의 일종임.

#### 비선점형 스케줄링
- 실행 상태에서 입출력 작업을 위해 대기 상태로 전환될 때만 수행되는 스케줄링 유형임.
- 어떤 프로세스가 CPU를 사용하고 있을 때 그 프로세스가 종료되거나 스스로 대기 상태에 접어들기 전까지는 다른 프로세스가 끼어들 수 없는 스케줄링 방식을 말함.

| 구분 | 선점형 스케줄링 | 비선점형 스케줄링 |
| :--- | :--- | :--- |
| **장점** | 한 프로세스의 CPU 독점을 막고 여러 프로세스에 골고루 CPU 자원을 분배할 수 있음. | 문맥 교환의 횟수가 적어 상대적으로 오버헤드의 발생은 적음. |
| **단점** | 문맥 교환 과정에서 오버헤드가 발생함. | 어떤 프로세스가 CPU를 사용 중이라면 당장 CPU를 사용해야 하는 프로세스라도 기다려야 함. |

## CPU 스케줄링 알고리즘
### 1 선입 선처리 스케줄링
- `준비 큐`에 삽입된 순서대로 CPU를 할당하는 스케줄링 방식임.
- 프로세스들이 기다리는 시간이 매우 길어질 수 있다는 문제가 있음.
- **`호위 효과`**: 먼저 삽입된 프로세스의 오랜 실행 시간으로 인해 나중에 삽입된 프로세스의 실행이 지연되는 문제를 말함.

### 2 최단 작업 우선 스케줄링
- `준비 큐`에 삽입된 프로세스 중 CPU를 이용하는 시간의 길이가 가장 짧은 프로세스로부터 먼저 실행하는 스케줄링 방식임.
- 기본적으로 `비선점형 스케줄링` 알고리즘으로 분류되지만, `최소 잔여 시간 우선 스케줄링` 형태로 `선점형`으로 구현되기도 함.

### 3 라운드 로빈 스케줄링
- **타임 슬라이스**: 프로세스가 CPU를 사용하도록 정해진 시간을 의미함.
- 큐에 삽입된 프로세스들이 삽입된 순서대로 CPU를 이용하되, 정해진 `타임 슬라이스`만큼 CPU를 이용하는 `선점형 스케줄링`임.

### 4 최소 잔여 시간 우선 스케줄링(SRT)
- `최단 작업 우선 스케줄링`과 `라운드 로빈 스케줄링`을 합친 스케줄링 방식임.
- 프로세스가 정해진 `타임 슬라이스`만큼 CPU를 이용하되, 남아 있는 작업 시간이 가장 적은 프로세스를 다음 프로세스로 선택함.

### 5 우선순위 스케줄링
- 프로세스에 우선순위를 부여하고, 가장 높은 우선순위를 가진 프로세스로부터 실행하는 스케줄링 방식임.
- **아사 현상**: 우선순위가 낮은 프로세스가 우선순위가 높은 프로세스로 인해 계속해서 실행이 연기되는 현상임.
- `아사 현상`을 방지하기 위해 `에이징` 기법을 사용하는데, `에이징`은 오랫동안 대기한 프로세스의 우선순위를 점차 높이는 방식임.

### 6 다단계 큐 스케줄링
- `우선순위 스케줄링`의 발전된 형태로, 우선순위별로 여러 개의 `준비 큐`를 사용하는 스케줄링 방식임.
- 우선순위가 가장 높은 큐에 삽입된 프로세스부터 처리하며, 해당 큐가 비어 있어야 그 다음 우선순위 큐에 삽입된 프로세스에 CPU를 할당함.

### 7 다단계 피드백 큐 스케줄링
- `다단계 큐 스케줄링`과 비슷하게 동작하지만, 프로세스들이 큐 사이를 이동할 수 있다는 점이 다름.
- 새롭게 진입하는 프로세스는 우선순위가 가장 높은 큐에 삽입되고, `타임 슬라이스` 동안 실행이 끝나지 않으면 점점 낮은 우선순위 큐로 이동함.
- 이로 인해 CPU를 오래 사용하는 `CPU 집중 프로세스`오의 우선순위는 점점 낮아지고, `입출력 집중 프로세스`들은 우선순위가 높은 큐에서 빠르게 실행이 끝남.
- 여기서도 `에이징` 기법을 적용해 낮은 우선순위 큐에서 오래 기다리고 있는 프로세스들을 높은 우선순위 큐로 이동시킬 수 있음.

## 리눅스 CPU 스케줄링
- 리눅스에서는 5가지의 스케줄링 정책을 사용함.

| 스케줄링 정책 | 적용 상황 |
| :--- | :--- |
| `SCHED_FIFO` / `SCHED_RR` | 실시간성 프로세스에 적용되는 정책<br>(매우 높은 우선순위를 할당함) |
| `SCHED_NORMAL` | 일반적인 프로세스에 적용되는 정책 |
| `SCHED_BATCH` | 일반적인 프로세스만큼 자주 선점하지 않는 배치 작업에 적용되는 정책 |
| `SCHED_IDLE` | 우선순위가 매우 낮은 프로세스에 적용되는 정책<br>(매우 낮은 우선순위를 할당함) |

- `SCHED_NORMAL`에서는 `CFS`라는 CPU 스케줄러에 의해 스케줄링이 이루어짐.
    - **`CFS`**: 프로세스에 대해 완전히 공평한 CPU 시간 배분을 지향하는 CPU 스케줄러임.
    - 리눅스에서는 프로세스마다 `가상 실행 시간`(`vruntime`)이라는 정보를 유지하는데, `CFS`는 이 `vruntime`이 가장 작은 프로세스부터 스케줄링함.
    - `vruntime` = (CPU를 할당받아 실행된 시간) * (평균 가중치 상수 / 프로세스의 가중치) 이며, 프로세스 가중치는 우선순위와 연관된 값으로 프로세스의 우선순위가 높아지면 가중치도 높아짐.
    - `타임 슬라이스` = (프로세스의 가중치 / `CFS` 대기 큐에서 대기하는 프로세스들의 전체 가중치) * (`CFS` 큐에서 대기하는 프로세스들의 타임 슬라이스 전체 합)임.
    - `프로세스의 가중치`가 높을수록 **먼저 스케줄링될 확률이 높고**, `타임 슬라이스`도 크게 할당받을 수 있음.
    - 리눅스 운영체제에서는 `/proc/<PID>/sched` 파일을 출력하는 명령어로 `vruntime`과 가중치를 확인할 수 있음.
