## 1. 운영체제의 큰 그림

- **운영체제(OS)**: 응용 프로그램이 하드웨어 자원(CPU, 메모리 등)을 사용할 수 있도록 중간에서 관리하고 배분하는 특별한 프로그램
- **커널(kernel)**: 운영체제의 핵심 기능을 담당하는 부분

### 운영체제의 역할

- CPU, 메모리, 보조기억장치 등 컴퓨터 부품에 접근하고 효율적으로 사용되도록 관리하며, 응용 프로그램에 자원을 할당함.
- 동시에 실행되는 프로세스와 스레드의 실행 순서를 제어하고, 필요한 자원을 적절히 배분함.

> 응용 프로그램은 자원에 직접 접근할 수 없으며, 운영체제가 대신하여 자원에 접근하고 관리함.

#### 자원 관리 방식

- **CPU 관리: CPU 스케줄링**
  - CPU는 한정된 자원이므로 모든 프로그램이 동시에 사용할 수 없음.
  - 운영체제가 CPU 할당 순서와 사용 시간을 결정함.

- **메모리 관리: 가상 메모리**
  - 운영체제는 새 프로그램을 메모리에 적재하고, 종료된 프로그램을 삭제하며 효율적으로 관리함.
  - **가상 메모리**: 실제 물리적인 메모리 크기보다 더 큰 메모리를 이용할 수 있도록 하는 기술

- **파일/디렉터리 관리: 파일 시스템**
  - **파일 시스템**: 보조기억장치 내의 정보를 파일 및 폴더(디렉터리) 단위로 접근하고 관리할 수 있도록 만드는 운영체제 내부 프로그램

- **프로세스 및 스레드 관리**
  - **프로세스(process)**: 실행 중인 프로그램
  - **스레드(thread)**: 프로세스를 이루는 실행의 단위
  - 운영체제는 프로세스에 자원을 할당하고, 스레드는 할당받은 자원을 이용해 작업을 수행함.

## 운영체제 지도 그리기

```
운영체제
├── 프로세스 및 스레드 관리
│   ├── 프로세스와 스레드
│   └── 동기화와 교착 상태
│
└── 자원 할당 및 관리
    ├── CPU 관리: CPU 스케줄링
    │   ├── 기본 개념 – 우선순위, 스케줄링 큐, 선점형과 비선점형
    │   ├── CPU 스케줄링 알고리즘
    │   └── 리눅스 CPU 스케줄링
    │
    ├── 메모리 관리: 가상 메모리
    │   ├── 물리 주소와 논리 주소
    │   ├── 메모리 할당
    │   └── 페이징과 페이지 교체 알고리즘
    │
    └── 파일/디렉터리 관리: 파일 시스템
        ├── 파일과 디렉터리
        └── 파일 시스템
```

### 시스템 콜과 이중 모드

운영체제는 메모리 내 **커널 영역**에 적재되어 실행되고, 응용 프로그램은 **사용자 영역**에 적재됨.

| 영역 | 설명 |
|---|---|
| **커널 영역(kernel space)** | 운영체제가 적재되는 메모리 공간 |
| **사용자 영역(user space)** | 사용자 응용 프로그램이 적재되는 메모리 공간 |

**시스템 콜(system call)**
- 응용 프로그램이 운영체제의 서비스를 제공받기 위한 수단(인터페이스)
- 응용 프로그램은 시스템 콜을 호출해 운영체제 코드를 실행함.

**대표적인 시스템 콜 종류 (유닉스 계열)**

| 구분 | 시스템 콜 | 설명 |
|---|---|---|
| 프로세스 관리 | `fork()` | 새 자식 프로세스 생성 |
| | `execve()` | 프로세스 실행 |
| | `exit()` | 프로세스 종료 |
| | `waitpid()` | 자식 프로세스 종료 대기 |
| 파일 관리 | `open()` / `close()` | 파일 열기 / 닫기 |
| | `read()` / `write()` | 파일 읽기 / 쓰기 |
| | `stat()`  | 파일 정보 획득 |
| 디렉터리 관리 | `mkdir()` / `rmdir()` | 디렉터리 생성 / 삭제 |
| | `chdir()` | 작업 디렉터리 변경 |
| 파일 시스템 관리 | `mount()` / `umount()` | 파일 시스템 마운트 / 해제|

**시스템 콜 처리 흐름**

```
[1] 소프트웨어 인터럽트 발생
       ↓
[2] CPU의 커널 모드 전환
       ↓
[3] 운영체제 코드 실행
       ↓
[4] 사용자 모드로 재전환
```

**이중 모드(dual mode)**
- CPU가 사용자 영역과 커널 영역을 구분하여 실행하는 방식

| 모드 | 설명 | 명령어 실행 권한 |
|---|---|---|
| **사용자 모드** | 사용자 영역 코드 실행 | 자원 접근 명령어 실행 불가 |
| **커널 모드** | 커널 영역 코드 실행 | 모든 명령어 실행 가능 |

- CPU가 현재 어느 모드로 실행 중인지는 **플래그 레지스터 속 슈퍼바이저 플래그**로 확인 가능함.

> `hello world`를 출력하는 단순한 프로그램조차 실행 과정에서 600회가 넘는 시스템 콜을 호출함. 프로그램은 실행 중 사용자 모드와 커널 모드를 빈번히 오가며 동작함.
