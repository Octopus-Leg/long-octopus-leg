# 8. API 테스트

## 1️⃣ API와 코드를 수동으로 테스트하기
- 테스트는 가능한 모든 **유즈 케이스**와 변경된 코드를 커버해야 하며 개발 및 유지 보수 과정에서 지속적으로 실시해야 함.
- **단위 테스트**, **통합 테스트**, **컨트랙트 테스트**, **종단 간(E2E) 테스트**, **사용자 수락 테스트(UAT)** 등의 유형이 있음.
- 수동 테스트는 `cURL`이나 `포스트맨`을 사용하며, 모든 API를 테스트하지 않으면 프로덕션에서 문제가 발생하고 패닉이 발생할 수 있음.
- **타임 투 마켓(TTM)** 이 중요한 오늘날의 소프트웨어 산업에서 품질 검사는 릴리즈 주기에서 가장 중요한 부분임.
- 테스트 프로세스를 자동화하고 `CI/CD` 파이프라인에 통합하면 테스트 시간을 줄이고 **지속적인 통합(CI)** 과 **지속적 전달(CD)** 를 실현할 수 있음.

## 2️⃣ 테스트 자동화
- 수동으로 수행하는 모든 테스트는 **자동화**를 통해 빌드 과정의 일부로 추가할 수 있음.
- 모든 변경과 코드 커밋에 대해 **테스트 스위트**를 실행하며, 모든 테스트를 통과한 경우에만 빌드가 성공함.
- `cURL`이나 `Insomnia`를 사용해 수동으로 실행하는 대신 빌드 과정에서 자동으로 API를 실행하고 결과를 확인함.

### 단위 테스트
- `spring-boot-starter-test` 의존성을 사용하여 `JUnit 5`, `Mockito`, `AssertJ`, `Hamcrest` 등을 활용함.
- **단위 테스트**는 테스트 가능한 가장 작은 코드 단위(클래스 메소드 등)를 테스트하며, 가볍고 빠르게 실행되어야 함.
- 실제 데이터베이스나 인프라 서비스에 의존하는 대신, **모의 객체(mock)** 를 생성하여 테스트를 빠르게 해 개발자가 빌드를 더 신속하게 할 수 있음.

### AssertJ 어서션을 사용해 테스트하기
- **AssertJ**는 유창한 API를 제공하여 어서션 작성을 단순화하고 가독성을 높여주는 라이브러리임.
- `@Mock`으로 서비스나 어셈블러 등의 모의 객체를 정의하고, `@InjectMocks`를 통해 테스트 대상 컨트롤러에 의존성을 자동으로 주입함.
- `MockMvc`를 사용해 실제 서버를 구동하지 않고도 **엔드포인트 URI**를 호출하여 컨트롤러 메소드를 실행함.
- `JacksonTester`를 사용해 JSON 응답이 기대하는 객체와 일치하는지 비교하는 어서션을 수행함.
- `ReflectionTestUtils.invokeMethod()`를 사용하여 접근이 제한된 **프라이빗 메소드**를 호출해 테스트함.
- 결과가 없는 메소드는 `doNothing()`을 사용하고, 예외 시나리오는 `willThrow()`를 사용해 검증함.

### 코드 커버리지
- 테스트가 소스 코드를 얼마나 실행했는지 측정하며, **라인 커버리지**와 **브랜치 커버리지** 메트릭을 제공함.
- `JaCoCo` 플러그인을 `build.gradle`에 추가하여 측정하고 HTML 리포트를 생성함.
- `exclude` 블록을 구성하여 모델이나 보안 설정 등 테스트가 불필요한 패키지를 측정 대상에서 제외함.
- `violationRules`에서 `minimum` 값을 설정하여 (예: 0.9) 최소 커버리지 기준을 충족하지 못하면 빌드가 실패하게 함.

### 통합 테스트하기
- 모의 객체를 사용하지 않고 컨트롤러부터 **데이터베이스(H2 등)** 까지 모든 애플리케이션 계층을 테스트함.
- `build.gradle`에 별도의 `sourceSets`와 `integrationTest` 태스크를 설정하여 단위 테스트와 물리적으로 분리함.
- `@SpringBootTest`와 `WebEnvironment.RANDOM_PORT`를 사용하여 실제 스프링 컨텍스트를 로드함.
- `TestRestTemplate`을 사용하여 실제 REST 엔드포인트에 요청을 보내고 응답 결과의 유효성을 검증함.
